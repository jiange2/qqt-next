# 本地音乐以用户授权的音乐文件夹为来源，不使用 MediaStore 全机索引

底部导航的「最近播放」页将改造为「本地音乐」页，展示用户设备上的音频文件。决定：通过 SAF（`ACTION_OPEN_DOCUMENT_TREE`）让用户指定音乐文件夹，用 `takePersistableUriPermission` 持久化授权，App 自行递归遍历目录树；不申请 `READ_MEDIA_AUDIO` / `READ_EXTERNAL_STORAGE`；标签用 `MediaMetadataRetriever` 从 content URI 读取。理由是「本地音乐」在语义上就是"我选中的那些文件夹"，而 MediaStore 只能表达"整机所有音频"，两者不等价；SAF 还把授权范围交给用户、只在选择目录时授权一次，不产生全盘读取的权限弹窗。

## Considered Options

- **MediaStore 全机索引（否决）**：自带增量与元数据字段，但视野是整机——无法只扫用户指定的目录，必须靠 `IS_MUSIC`、时长等条件猜测哪些算音乐，会把其它 App 的录音、铃声一并卷进来。
- **MediaStore 按路径前缀过滤（否决）**：仍要申请整机音频读取权限，权限范围与功能范围不匹配；且用户换文件夹时过滤逻辑散在查询条件里。
- **SAF 目录授权（采纳）**：权限范围 = 用户选中的树，递归与过滤由我们自己掌握，Android 5.0 起行为一致。

## Consequences

- 不涉及存储权限；首次进入本地音乐页时无内容是正常的，需要显式的「选择音乐文件夹」入口。
- SAF 不提供变更通知：文件夹内容变化后列表会滞后，只能靠用户触发的重新扫描收敛。
- 文件夹被删除、移动或授权被系统回收时，本地音乐整体变空，必须有重新选择路径的引导。
- 首次扫描要对每个文件读取标签，大目录的 I/O 成本与目录规模成正比，不能放在主线程或页面首帧。
- App 私有目录里的下载文件不在扫描范围内，「下载列表」与「本地音乐」是两个互不包含的集合。
- 同一份音乐授权两个重叠的目录树时，扫描结果需要按歌曲身份去重，不能出现两份。
