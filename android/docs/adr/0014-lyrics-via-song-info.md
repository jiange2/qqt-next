# 歌词取数复用 song_info 详情接口，接受其播放量计数副作用

安卓端歌词恒显「暂无歌词」的根因：歌词字段（mp3_lrc_txt / mp3_lrc_url）只在 song_info / single_song 详情接口下发，全部列表接口不携带，而安卓从未调用过详情接口——歌词链路从未接通，与后台上传无关。决定由安卓按需调用现有 song_info（method_name=song_info & song_id=…）取歌词：请求点为用户滑到歌词页（而非播放器打开即取）；响应只取歌词两字段使用，不替换队列中的 Song 对象；结果入歌词会话缓存（LyricsCache），同一首歌每会话至多请求一次。

song_info 在两个后端都带「详情请求计一次播放」副作用（PHP：total_views+1 加周度表 upsert；backend-next：totalViews+1，周度表已按其 ADR 0003 移除）。决定保留该副作用：旧 demo 客户端的播放统计完全依赖它，剥离会使旧客户端统计归零；安卓侧把请求点收窄到「看歌词的人次」（与播放强相关），残余灌水为每首歌每会话至多一次，被接受。响应快照白名单纳入 song_info（ADR 0012 的扩展）：回放走本地构造不触网，副作用不会重放。

## Considered Options

- **列表接口携带歌词字段**：一次下发零二次请求，但响应体积膨胀（歌词纯文本不小）且列表场景几乎用不到歌词。否决。
- **新增专用歌词接口 get_lyrics**：响应最轻，但属协议变更须门面评审，PHP 与 backend-next 两侧都要新增；song_info 已在两侧就绪。否决。
- **安卓调用 song_info 且剥离其播放量副作用**：语义最干净，但旧 demo 客户端的播放统计依赖该副作用。否决剥离，保留副作用并以请求点收窄灌水量。
- **安卓按需调用 song_info（采纳）**：后端零协议变更、backend-next 详情响应已带歌词字段、响应快照天然覆盖离线回放。

## Consequences

- 播放量统计语义从「点播播放」漂移为「点播播放 + 看歌词的人次」，漂移量级为每首歌每会话至多一次；将来做严肃播放统计时应另立独立的播放上报接口，不应继续依赖详情接口副作用。
- 歌词占位拆分两态：「暂无歌词」（歌曲本无数据，终态）与「歌词加载失败」（取回/解析失败，提供重试），见 Android CONTEXT.md「歌词」词条。
- PHP 后端顺带修复：mp3_lrc_url 为空时不再拼出指向 lrc/ 目录的伪 URL；mp3_lrc_txt / mp3_description 的 addslashes 双重转义移除（Insert/Update 内已有 real_escape_string，历史脏数据重存一次即刷新）。
- backend-next 迁移时 lrcUrl() 丢失了该空值处理，空歌词文件名仍拼出 base+'lrc/' 伪 URL，App 端歌词页恒显「歌词加载失败」而非「暂无歌词」；后修复为无歌词文件时输出空串，与 PHP 行为对齐（当初采纳理由中「含空值保护」的陈述系未经空值路径验证的误记，已更正）。
