# Android 缓存预算公式：总容量预留制替代 60% 空闲快照

旧公式取「启动时刻空闲空间 × 60%」作为 SimpleCache 的 LRU 逐出上限，缺陷在于它只表达快照时刻的相对余量：其他 App 动态写盘后预算失真（空闲仅剩 1G 时缓存仍自认为有数十 G 配额），预留线完全失效。现改为总容量预留制：预算 = max(启动时刻空闲空间 − max(总容量×5%, 1GB), 0)，即 100G 设备最多用 95G、10G 设备最多用 9G。

## Considered Options

- **实时重算（自定义 CacheEvictor）**：每次逐出决策实时重算，运行期预留线始终成立。否决：需自定义逐出器，实现重；前台服务虽可长驻，但进程重启重新快照的收敛频率可接受。
- **上报时周期检查**：随访问事实/切歌检查实时空闲并手动触发逐出或重建。否决：两套逐出路径，复杂度与收益不成比例。
- **仅启动时重算（采纳）**：仅替换公式，保留快照模型，实现面最小。

## Consequences

- 预留线只在启动那一刻成立：长驻进程期间外部写盘击穿预留线不会被本进程感知，靠进程重启重新快照纠正（已接受的残留风险）。
- 预算为 0（启动时刻空闲 − 预留量 ≤ 0）时照常初始化 SimpleCache，LRU 清空已有缓存、后续即写即删，不设最小预算地板。
- `allocated_storage` 上报语义变为「本次进程会话的预算快照」，随访问事实照旧携带，后端 upsert 无需改动（ADR-0032 的 used_storage 快照口径不受影响）。
