# 本地歌曲的元数据修改只做 App 内覆盖层，不回写文件标签

本地音乐支持修改歌曲的标题、艺术家、专辑等元数据。决定：修改只写入 App 本地的覆盖层，音频文件本身不动；列表、播放器、专辑分组一律展示"文件标签叠加覆盖值"后的结果。理由是回写标签在 Android 10+ 属于跨应用写共享存储：修改其它 App 创建的文件需要 `MediaStore.createWriteRequest()` 逐次弹窗授权或 SAF 写授权，只读存储会失败，重写标签还有损坏用户文件的风险——为了一个展示需求去动用户的原文件，收益与风险不成比例。

## Considered Options

- **直接回写文件标签（否决）**：其它播放器能看到修改，但需要逐文件的写授权与失败分支，且可能损坏原文件。
- **覆盖层 + 手动「写回文件」（否决本期）**：覆盖层解决展示，写回作为附加动作。本期需求只要求"改"，未要求"改到文件里"；写回需要第二套授权与失败处理，等有明确需求再做。
- **只做 App 内覆盖层（采纳）**：无授权、无写失败、不动用户文件。

## Consequences

- 其它播放器与本 App 会看到不同的标题/专辑，这是有意为之的取舍。
- 同一首歌存在两个真相：「文件标签」和「显示值」。所有展示路径必须统一取覆盖后的值，任何直接读 `MediaMetadataRetriever` 结果的地方都算 bug。
- 覆盖层以歌曲身份为键存储，键在重扫描、文件移动后是否仍然命中，直接决定用户改过的元数据能否保住。
- 「恢复默认」等于删除该歌曲的覆盖项，不需要备份原标签。
