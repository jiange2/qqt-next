# 用户自建歌单仅存本机

播放器功能图标行第四位（原评论占位）接通「加入歌单」时，需要一个添加目标。后端播放列表是管理员策展合集，维护走管理后台的 `song_ids` 全量替换；App 尚无登录系统（ADR 0005，`user_id` 恒为 0），后端也没有任何面向客户端的写接口，放开写入意味着所有游客共写管理员策展池。故按收藏的本机先例，新增本地歌单实体：仅存本机、不随账号同步、歌单数与单曲数不设上限不自动驱逐；「我的列表」页（旧页与后端「播放列表」页数据重复，且新建按钮、播放、更多三处均为空回调）重定义为本地歌单的家。

## Considered Options

- **加入后端播放列表**：需新建客户端写接口与身份隔离；未登录形态下游客共写同一池、污染管理员策展语义。否决。
- **仅追加到播放队列**：纯客户端改动最小，但播放队列每次点播被整体替换、会话级存续，「加入列表」的拥有语义不成立。否决。
- **本地歌单（采纳）**：LocalPlaylistStore 作事实来源、PrefsManager 持久化 Gson 快照（仿收藏模式）；只存歌曲 ID，经 `get_recent_songs` 按 ID 换详情（与收藏页同构）；UI 与词表统一用「歌单」，「播放列表」四字保留给后端策展合集。

## Consequences

- 本地歌单不跨设备同步；卸载 App 即丢失（已接受的未登录形态限制）。
- 歌单内歌曲被后台下架后从歌单详情消失但本地 ID 保留，重新上架自动回来。
- 术语成本：全 App 界面不得用「播放列表」指代本地歌单，抽屉旧文案「我的列表」改为「我的歌单」。
- 登录系统上线后需迁移：本地歌单批量写入按用户隔离的后端存储，届时本 ADR 标记 superseded。
