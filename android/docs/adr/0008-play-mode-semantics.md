# 播放模式三态，「顺序播放」= 顺序循环整个队列

主控行左端的循环按钮在接通前是纯 UI 摆设：本地 `remember` 三态（不循环/全队列循环/单曲循环），而引擎侧 ExoPlayer 自始恒定 `REPEAT_MODE_ALL`，点击不影响任何行为。参照外部设计稿的三项菜单（随机播放/顺序播放/单曲循环，另含本 ADR 明确不做的「设置次数」）接通真实播放模式时，在"贴设计稿"与"行业惯例（顺序播放=播完即止）"之间选择贴设计稿：**「顺序播放」定义为按队列顺序循环整个队列（`REPEAT_MODE_ALL`，即引擎历史行为），不提供"播完即止"态**。随机播放 = 乱序 + 整队列循环（一轮随机完重新随机再来）；单曲循环 = `REPEAT_MODE_ONE`。默认顺序播放，模式持久化于 `player_settings`（PlayerSettingsManager），Service 收集变化落到 ExoPlayer。

## Considered Options

- **行业惯例三态（随机/顺序播完即止/单曲循环）**：砍掉循环会让升级后队列放完自动停，属于行为退化。否决。
- **四态全覆盖（随机/顺序播完即止/列表循环/单曲循环）**：不退化但菜单比设计稿多一项，「顺序播完即止」无需求来源。否决。
- **三态贴设计稿（采纳）**：与参考视觉一致、引擎行为零突变；代价是「顺序播放」名不副实，靠词表钉死语义。

## Consequences

- 「顺序播放」实际是无限循环。修改者请勿按行业惯例把它"修复"成播完即止——那是被否决的选项（CONTEXT.md 顺序播放条目已标注 Avoid: 列表循环）。
- 引擎不出现 `REPEAT_MODE_OFF` 组合；图标点击轮转顺序与菜单展示顺序同为 随机 → 顺序 → 单曲循环。
- 旧「循环模式」按钮的本地三态（NONE/ALL/ONE）连同"不循环"语义一并废除；设置持久化后跨启动保持，升级用户无感知突变（默认即历史引擎行为）。
