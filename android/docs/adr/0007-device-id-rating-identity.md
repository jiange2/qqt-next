# 评分以设备 ID 归属而非账号

播放器「更多」菜单接通评分时，后端 `song_rating` 接口早已存在（1–5 星、每人每首仅一次、不可改分，按 `user_id` 判重并把归属存入 `tbl_rating.ip` 列）。而 App 无登录系统，所有接口 `user_id` 恒为 0（见 ADR 0005）——评分若继续传 0，全体游客共享同一评分身份，第一人评完后其余所有人都撞「已评分」拒绝。故引入设备 ID：本机首次评分前生成 UUID 持久化于 SharedPreferences，仅评分请求携带，其余请求维持 `user_id=0` 不动。已评状态另记本地（歌曲 → 星级），用于已评态展示与禁止重复提交；后端 `rate_already` 作为本地记录丢失（卸载重装）时的兜底提示。

## Considered Options

- **沿用 user_id=0**：全体游客共享同一评分身份，第一人评分后其他所有人都无法再评。否决。
- **系统 ANDROID_ID**：无需自生成，但无 GMS 环境、恢复出厂等场景取值不受控，身份稳定性无法保证（目标设备以国内 ROM 为主）。否决。
- **本次顺带做登录系统**：登录、注册、token 一整套，与「接通评分」不在一个量级（同 ADR 0005 的否决理由）。否决。
- **自生成设备 ID（采纳）**：可控、稳定、改动面收敛在评分一个请求点；代价是不可跨设备、卸载即失（与本地收藏、本地歌单同一未登录形态限制）。

## Consequences

- 同一人在不同设备可各评一次（设备即身份的固有限制，已接受）。
- 卸载重装后本地已评记录丢失：重新评分会撞后端 `rate_already`，提示「已评分过」并把本次所选星级记入本地；后端真实记录的星级 App 不回显（不调 `single_song`，该接口每次调用会给歌曲播放量 +1），不一致不可见，本机自洽。
- 评分对话框不展示平均星级/评分人数（保持最简）；歌曲的统计评分仍在各列表的 SongListItem 展示。
- 未来引入账号体系时需把 `tbl_rating.ip` 中的设备 ID 迁移到账号（或建映射表），本 ADR 届时标记 superseded。
