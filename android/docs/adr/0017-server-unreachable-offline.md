# 服务器不可达（两入口连接失败或 5xx）也进入离线降级

响应快照（[ADR 0012](0012-offline-response-snapshot.md)）原设计在断网（ConnectivityManager 判定）与请求 IOException 兜底时回放，可感知的离线态（横幅）只挂在手机无网上。实测缺口（2026-09-14 用户报告"服务器崩掉不触发离线模式"）：反代 502 与后端/MySQL 500 是"成功的 HTTP 响应"、不抛 IOException，完全绕过回放；连接层失败时又因快照拦截器实际位于 failover 内层（注册顺序与 ApiClient 注释声称的"failover 先重试、快照最后兜底"相反），命中快照的请求直接回放、回退重试被架空。决定新增进程内粘性态「服务器不可达」（术语入 android/CONTEXT.md 网络节）：触发面为主用与回退地址均连接层失败、或服务端返回 5xx（500/502/503/504 一视同仁，不先试回退——同机回退与主域同命，5xx 是应用层答复）；进入后读操作秒回快照、同时后台静默发真实请求探测（搭在自然读请求上，无独立定时器），任一请求成功即退出；横幅复用断网同款、仅换文案「服务暂不可用，展示最近一次内容」（断网保持「当前离线，展示最近一次内容」，两因并存显示断网文案）；恢复不打断当前页面——退出态即可，横幅消失即信号，下次加载自然取新数据。写请求、非白名单请求（含上报）的判定性失败同样进入该状态（状态是服务级信号），但它们不回放、维持失败提示（ADR 0012 口径，不做 Outbox）。

配套顺序修订：快照拦截器移到 failover 外层（注册顺序调换），连接失败必须先走完主用+回退两次尝试才回放——这是"两入口都失败 ≡ 服务器不可达"判定的前提，也恢复 ADR 0009 的实际行为。回退粘性、连接层失败判定口径（DNS 解析失败/拒连/主机不可达/连接超时；读超时不算）均不变；读超时维持现状（命中快照仍由 IOException 兜底回放，但不进状态、不触发回退）。

## Considered Options

- **5xx 也先试回退、两入口都失败才判定**：拒——同机回退与主域同命，多一次请求换不来判定质量。
- **500 只做单请求回放、仅 502/503/504 进全局态**：拒——MySQL 挂掉时全员 500 与网关 502 对用户是同一件事；按状态码猜测故障层级，反代配置一变即失准。
- **保持快照在内层（命中即回放、不试回退）**：拒——域名故障但服务器活着时访问过的页面只能看旧快照；且只能以"主用失败"判定，会把纯域名故障误判为服务器不可达。
- **读超时纳入判定**：拒——ADR 0009 已判定"读超时=后端在响应但慢"，与"崩了"是两回事。
- **主动健康探测/独立定时器**：拒——无后端健康接口；探测搭自然读请求，恢复最多滞后一次读操作。
- **静默降级（不加横幅）**：拒——服务端故障应当被用户知道；"手机有网却提示离线"会误导，故按原因区分文案。

## Consequences

- ADR 0009 口径回到实际：命中快照的请求不再吞掉连接失败，域名故障期访问过的页面也经回退 IP 取新数据。**快照拦截器必须保持在 failover 外层，调回内层会让本 ADR 的判定前提失效。**
- 判定与回放只认主用/回退入口的请求（`ApiClient.entryHosts`）：CDN 歌词等非入口地址既不触发进态，粘性态中也照常回源——手机在线时 CDN 独立于服务器可用，失败自然走 IOException 兜底回放。
- 服务器全死时首个失败请求付主用+回退两次失败成本（拒连瞬时；挂起型约 5s+5s 后才进态），此后读操作秒回快照。
- 单接口 5xx 会短暂误进状态，任一请求成功即自愈；同一故障因延迟落在读超时还是 5xx 会造成行为摇摆（读超时走兜底回放、不进态），属已接受的边界。
- 状态进程内、冷启动重置（与回退粘性同口径）：冷启动后首个判定失败才重新进入。
- 横幅新增第二条文案；两因并存显示断网文案（硬信号优先）。
