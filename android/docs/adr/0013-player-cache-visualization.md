# 播放器进度条缓存可视化：金色 = 整曲本地可得，未命中显缓存前缀

被动缓存首次获得可见信号：全屏播放器进度条三态染色——整曲本地可得（被动缓存整曲命中，或已下载歌曲的 file:// 本地播放）整槽染浅金（新增 `CachedGold #E6A23C`，整槽以 30% 透明度叠出，与 demo 项目 ADR-0031 同色同参；金色为进度条内唯一暖色且专属「整曲本地可得」语义，StarGold 保持评分星专属）；未整曲命中的流式播放态以 PlayerNavy 30% 浅条显示缓存前缀（自歌曲起点到首个缓存空洞的连续已缓存区间，跨会话留存），随 CacheDataSource 边播边写实时生长、长满即翻金；已播放段恒为实心 PlayerNavy 不染色——正在播放语义不被静态属性覆盖。载体收敛于全屏播放器进度条（歌曲页/歌词页共享同一组件），MiniPlayer 细条与各列表序号不扩散。前缀查询与 PlayerViewModel 现有 500ms 轮询合并，SimpleCache 同进程直查 spans，不引入独立刷新通道。本决策推翻术语表原「被动缓存用户不可感知」「完成度不产生任何可见状态」两条立场，术语表已同步修订（新增「缓存前缀」「缓存染色」词条）。

## Considered Options

- **bufferedPosition 当「缓存位置」**：Media3 现成、实现最省，但只反映本次会话装载进度——重进 App 后昨日部分缓存不可见，与「缓存位置」字面语义不符。否决，改用缓存前缀（SimpleCache spans 直查，与整曲命中 C4 口径同构）。
- **同色浅金延伸表示部分缓存（金色面积 = 缓存进度）**：一色一义最简。否决——金色升格为「整曲本地可得」状态信号，部分缓存只是过程信号，双色区分让翻金瞬间对比最强（用户裁决，偏离推荐）。
- **已下载歌曲不染金**：下载态已有 DownloadedGreen 信号链路，金色专注被动缓存事实。否决——统一为「整曲本地可得 = 金」，用户免学两种颜色差别（用户裁决，偏离推荐）。
- **复用 StarGold**：省一个 token，但评分星与缓存语义共色、各自演化必牵连。否决，新增 CachedGold。

## Consequences

- 被动缓存由「不可感知」改为「不可管理但一处可见」，术语表两条修订已落档；UI 不出现「缓存」字样，纯颜色信号。
- 前缀口径在 seek 留洞时于首个空洞截断，表达「到此位置之前整段可离线重播」，而非全文件字节比例。
- 装载时刻的 C4 整曲命中口径（访问事实上报）不变；播放中长满翻金是前缀生长的自然结果，上报不受可视化影响。
- file:// 播放不经 SimpleCache，无前缀数据，直接归「整曲本地可得」翻金。
