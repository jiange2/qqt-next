# 播放器封面：歌曲封面圆角方形 + 封面主色亮色化动态背景

全屏播放器原先对封面无设计（圆形直出、切歌硬切、加载/失败无区分），背景为固定极光图。本次设计（grilling 会话定稿）明确：封面数据源是**歌曲封面**（歌曲自带的 `thumbnailBig`），不是专辑实体的封面——客户端不打通 Song→Album 链路（术语见 CONTEXT.md「歌曲封面」，Avoid「专辑封面」）。封面呈大圆角方形（24dp、1:1、阴影保留，高度自适应机制不变），切歌时淡入 + 0.95→1.0 缩放进场，暂停时压暗降饱和，加载中/失败/无 URL 统一显示音符占位；封面不可点，因此不提供按压反馈（遵守 CONTEXT.md「按压反馈」：设计上不可操作的态不提供按压反馈）。

背景从固定极光图升级为封面主色的**亮色化垂直渐变**（顶部主色浅版 → 底部近白）：Palette 提取主色后掺白到保证藏青控件可读的亮度，主色按歌曲缓存。关键取舍是**只动背景一层**：标题/图标/进度条维持藏青灰系、状态栏维持深色图标，零控件改动。封面未加载、加载失败或提取不出主色（纯白/透明图）时，回退到极光图 + 白蒙板。切歌时背景色约 400ms 平滑过渡（animateColorAsState），与封面动效同步，避免新旧背景硬切。

## Considered Options

- **暗色化背景（主色压暗 + 控件全部转白系 + 状态栏亮图标）**：否决——整页变暗色风格，与全 App 其余亮色页面割裂，改动覆盖所有控件，成本数倍且破坏全局一致性。
- **主色叠染极光图**：否决——两张视觉资产互相干扰，染色效果不可控。
- **维持固定极光背景**：否决——产品要每首歌的氛围差异，固定背景无此表达。

## Consequences

- 播放页背景随歌曲变化，主色需以歌曲 ID 为键缓存，避免切回已播放歌曲时重复提取。
- 极浅/纯白封面掺白后仍需亮度阈值兜底，防止藏青控件对比度不足（提取侧保证，不改动控件色）。
- 迷你播放器与通知栏 artwork 不在本次范围，维持各自现有策略（thumbnailSmall 优先 / thumbnailBig）。
