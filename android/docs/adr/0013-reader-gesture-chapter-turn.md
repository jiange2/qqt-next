# 阅读页手势翻章：左滑下一章的方向约定与松手触发

阅读页原有章首「上一章」、章尾「下一章」链接与目录点选三种翻章路径，连续阅读需把手指移到链接上点击，不够顺手。新增两条手势：「拖动翻章」——章尾继续上拖 / 章首继续下拖累计越界达阈值后松手翻入下一 / 上一章，拖动中提示文案随阈值切换；「滑动翻章」——水平滑动换章，左滑进入下一章、右滑回到上一章。两条手势均松手判定，与链接翻章共用同一换章逻辑（落新章章首、进度按章切换落盘）。正文区同时禁用系统拉伸过滚动（2026-09 修订）：越界拖动使到界成为高频动作，系统 stretch 的字形变形逐次残留、退出阅读页才重置，正文不可变形。

## Considered Options

- **右滑 = 下一章（曾实现，已回退）**：「仿真书页向前翻」的方向，与主流阅读 App 和播放器横滑切页都相反；真机验证后判定反直觉而回退——根因是口头需求「往右滑到第二章」同时可指手指向右或内容向右，确认时未对齐参照系。
- **左滑 = 下一章（采纳）**：行业惯例（微信读书等主流阅读 App），与本 App 全屏播放器「横滑切页」方向一致，全 App 手势心智统一。手势描述一律用目标态（「滑向下一章」），勿用左滑/右滑。
- **达阈值立即翻（无需松手，抖音竖滑式）**：响应最快，但阅读场景误触代价高（一翻即离开当前章位置）。否决，改为松手才翻，并在章尾/章首提供「继续拖动… / 松手进入…」两段提示降低意外感。
- **越界拖动保留系统拉伸过滚动（曾保留，已回退）**：Android 12+ 列表到界的默认 stretch 效果把整块正文（含字形）纵向拉伸变形，高频到界下残留逐次累积、松手不回弹；改为阅读页正文禁用拉伸过滚动（与播放页队列浮层关光效同套路），边界反馈由章尾/章首两段提示文案承担。

## Consequences

- 手势为观察式实现：不消费触摸事件，列表滚动、链接点击、系统返回均不受影响；水平滑动起点避开屏幕左右边缘各 30dp，避免与系统边缘返回手势互相误触。
- 第一章章首无上一章、最后一章章尾无下一章，对应方向的手势复用 ViewModel 既有边界守卫，自动无操作。
- 手势不改变单章一屏模型（backend-next ADR 0011）：越界拖动不拼接下一章正文，仍是整章跳转。
- 阅读页正文禁用系统拉伸过滚动：正文不可变形优先于平台默认边界效果；禁用不影响手势判定（观察式实现不消费事件），到界反馈完全由提示文案承担，浮层（目录/设置）保留原生效果。
- 方向类手势需求必须在真机验证后才算确认：口头「往左/往右滑」有手指向与内容向双重歧义，本项目已因此纠偏一次。
