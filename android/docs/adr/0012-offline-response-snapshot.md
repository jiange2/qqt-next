# 断网降级用应用层「响应快照」，不使用 HTTP 缓存

浏览、搜索、阅读等发现域功能完全依赖在线请求，断网时全部失效（播放域已有主动/被动缓存与队列快照覆盖）。决定在 OkHttp 应用拦截器层实现「响应快照」：按业务语义 key（method_name + 业务参数，从 data 字段解码提取）留档非空有效的成功响应，断网（ConnectivityManager 判定）或请求失败（IOException 兜底）时回放最后一次留档，无过期时间；在线时始终发真实请求并回写覆盖。回放白名单覆盖全部只读接口，`app_details` 与全部写接口（评分、访问上报、时长写回）排除；`get_recent_songs` 因 key 含 ID 串（最近播放每多一首即变）特殊化为按歌曲 ID 的实体级缓存，回放时按请求重组。留档设独立小预算（约 5MB）LRU 驱逐，不并入音频缓存预算；存 cacheDir，用户不可感知不可管理；断网时 App 全局常显轻量横幅。歌词 `fetchText` 走同一 client 顺带纳入；封面图维持 Coil 默认磁盘缓存，不在本决策范围。

关键硬约束：协议是单一 `POST api.php` 且请求体含每次变化的时间戳 salt，同一业务的两次请求字节永不相同——HTTP 层缓存（OkHttp Cache / Cache-Control）在此协议下原理性不可行，只能按业务语义在应用层记响应。

## Considered Options

- **OkHttp Cache（HTTP 层）**：POST + 动态 salt，无法命中，原理性否决。
- **Repository 层逐方法包装**：14 个只读方法逐一改，且歌词通道（fetchText）覆盖不到。否决。
- **写操作 Outbox 排队重放**：评分有「每人每首仅一次、不可改分」强约束，离线排队有重复提交与状态错乱风险，收益极小。否决——写操作离线时维持现状提示失败。
- **OkHttp 应用拦截器（采纳）**：一处内聚 key 解码、白名单、回写口径与回放；Repository 与 ViewModel 零改动；歌词顺带覆盖。

## Consequences

- 响应快照是缓存家族第三成员（主动缓存/被动缓存均指音频，本词专指接口响应），口径为「不可感知不可管理」，随卸载与系统回收清理。
- 回写口径限定非空有效响应，后端临时故障返回的空列表不会覆盖既有快照。
- 断网回放与写操作失败提示并存：用户在断网时可浏览历史内容，评分等操作得到明确失败反馈而非静默丢弃。
