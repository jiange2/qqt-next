# 本地歌曲以内容指纹为身份，不用路径或 documentId 标识

本地歌曲需要在重扫描、文件移动、改名之后仍然被认成同一首歌，否则用户改过的元数据（ADR 0020 的覆盖层）会丢、去重也会失效。决定：歌曲身份 = 文件字节大小 + 首 32KB 与尾 32KB 的 SHA-256（文件不足 64KB 时取全文）；路径与 SAF documentId 只用于定位文件和重扫时快速跳过未变文件。理由是本地音乐的用户会整理文件夹、批量改名，而 ExternalStorageProvider 的 documentId 本质就是路径，任何路径型身份都会把这些正常操作变成数据丢失。

## Considered Options

- **路径 / documentId（否决）**：零成本，但改名或移动后身份断裂，覆盖层丢失、同一首歌在重叠目录里被当成两首。
- **仅「大小 + 修改时间」（否决）**：便宜且能扛住改名，但文件被其它工具 touch、重新复制后修改时间就变，身份随之漂移；覆盖层会莫名其妙失效。
- **内容指纹（采纳）**：移动、改名、换根目录都不影响；代价是首扫要读每个文件首尾各 32KB。

## Consequences

- 首扫对每个新文件读 64KB；重扫先用「路径 + 大小 + 修改时间」跳过未变文件，只有新增或变更的文件才计算指纹。
- 内容完全相同的两个文件被视为同一首歌，只展示一条（保留先扫到的那条路径）。同一首歌复制到两个文件夹不会出现两条。
- 覆盖层按指纹存取：文件移动或改名后自动恢复；文件被删除后覆盖层仍然保留，文件重新出现即生效。
- 指纹只看首尾：文件中间字节被改而首尾与大小不变时身份不变，但修改时间会触发元数据重读，展示值仍然正确。
- 指纹计算在扫描线程完成，任何情况下不能放在主线程或首帧。
