# 双层前台服务保活

> 已废止：被 [ADR 0014](0014-playback-scoped-fgs-keepalive.md) 取代——保活改由播放期前台服务承担。

App 同时运行两个前台服务：`MusicPlayerService`（承载播放）和独立的轻量 `KeepAliveService`（纯维持进程优先级），配合 `START_STICKY`、`onTaskRemoved` 不自杀、WiFi 锁与开机广播自启。

国产 ROM（小米/华为/OPPO/VIVO）对后台进程的查杀非常激进，单一前台服务存在被降级或回收的实际案例；双服务互为备份，即使一个被优化，进程优先级仍由另一个维持。代价是常驻两个前台通知（守护服务已降至 `IMPORTANCE_MIN` 以减少打扰）和略高的系统资源占用。这是针对目标用户群（国产设备为主）的刻意取舍，**不要因为"两个前台服务看起来多余"而合并它们**；若未来用户群变化或厂商策略放宽，可重新评估。注意 `ManufacturerCompat` 只能跳转到厂商自启动设置页，无法代为配置，白名单引导必须由用户手动完成。
