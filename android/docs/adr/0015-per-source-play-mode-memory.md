# 播放模式按队列来源记忆

ADR 0008 把播放模式做成单一全局设置（`player_settings` 的 `play_mode` 键，跨启动保持），但「专辑顺序听、歌单随机听」要求同一偏好在不同点播入口各不相同，单值做不到。决定按**队列来源**记忆播放模式：来源描述符五键 `album:{专辑ID}`、`local_playlist:{歌单UUID}`、`favourites`、`downloads`、`default`（首页瀑布流/热门/分类歌曲/搜索/艺术家/歌曲结果页等全部临时列表共享）；点播统一经 `PlayerViewModel.playSong` 以**必传** `sourceDescriptor` 参数打标（全部入口显式传入，编译器防漏标），队列内跳播不打标；播放器内切模式只写当前来源的记忆；`play_mode` 键语义重定义为「默认记忆」——临时列表共享、兼作新来源无记忆时的初值，零迁移。队列快照（ADR 0010）扩展 `source_descriptor` 字段，冷启动恢复读出后驻内存作为当前来源，存量快照无该字段记 `default`，不迁移；恢复对模式一律以来源记忆为准，快照不记模式——切模式同步写记忆、快照 5 秒轮询异步写，记忆恒比快照新鲜，自包含的模式字段无权威意义。PlayMode 三态、菜单轮转顺序、引擎 `REPEAT_MODE_*` 映射与全部 UI 不动。

## Considered Options

- **单一全局值（ADR 0008 现状）**：实现最简，但来源间互踩——专辑里切的随机会在歌单里生效，反之亦然。否决。
- **全局值 + 点播临时覆盖不记忆**：不落盘则行为不可预期——从专辑进是顺序、从首页进变随机，用户得不到解释。否决。
- **按来源记忆（采纳）**：诉求直达、升级用户无感知（默认记忆即历史全局值）；代价是来源标记须贯穿全部点播入口（必传参防漏标）、恢复路径来源驻内存、快照加一字段。

## Consequences

- ADR 0008 的「设置跨启动保持」修订为「按来源记忆跨启动保持」；三态语义、菜单顺序、引擎映射不动（CONTEXT.md 顺序播放条目的告诫原样有效）。
- ADR 0010 快照新增 `source_descriptor`；其「倍速与播放模式由既有持久化在连接后自动生效，恢复路径不重复处理」条款原样成立——恢复以来源记忆为准，不读快照模式（该字段不存在）。_（2026-09 注：倍速功能已移除，被引条款现仅播放模式部分成立。）_
- 未来新增点播入口必须显式归入五键之一：`sourceDescriptor` 无默认值，漏标是编译错误而非静默 `default`。
- 来源间模式互相独立是特性本意：专辑里切的单曲循环不会泄漏到歌单或临时列表；临时列表更新「默认记忆」也不影响任何已有记忆的来源。
- 记忆无 LRU 不设上限：仅删除本地歌单时删除其记忆（UUID 不复用，残留即死数据）；`favourites` / `downloads` / `default` 为常驻键永不清；专辑记忆永久保留；清空收藏/下载列表不动记忆（记忆是偏好，不是内容）。
