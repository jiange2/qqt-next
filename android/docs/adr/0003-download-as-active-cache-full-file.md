# 下载落地为完整文件，被动缓存随之迁入 filesDir

"下载"功能实为主动缓存：点"下载"把整首 MP3 流式落成 `filesDir/downloads/` 下的完整文件，以被动缓存（`AudioCache`）为上游数据源——已缓存字节零流量复用、只从网络补缺，同一机制覆盖"听完再下（秒下）/半缓存（补一半）/没缓存（全新下载）"三种起点；下载完成的文件永不自动驱逐、离线可直接播放（本地 URI）。被动缓存本身也从 `cacheDir/audio_cache` 迁到 `filesDir`（LRU 上限为启动时刻快照的缓存预算，见 ADR 0004），因为部分厂商 ROM 会定期清理 cacheDir，被动缓存放在那里会被系统性清空、丧失边听边存的价值。

之所以不用第二个 SimpleCache（自定义"永不驱逐"的 Evictor）来装主动缓存：SimpleCache 无法对单个条目钉住，双缓存链的查找/写入方向都复杂；完整文件则语义直白——一个可校验的文件就是"已下载"，天然支持断点续传（`.part` 文件 + 追加），离线播放直接换本地 URI，也不参与 LRU 与系统清缓存。

其余已定的边界：被动缓存旧数据不迁移（可再生）；下载不设人为总量上限，仅下载前按 Content-Length 校验可用空间；移动网络允许下载；进程内串行队列，进程被杀后不自动续传，下次点"下载"从断点继续；点"下载"不回调后端下载计数；下载入口仅在播放器操作栏（列表行不加），按钮状态机为 未下载 → 排队中 → 下载中（进度）→ 已下载（禁用），下载列表含进行中条目并经 More 菜单删除（删除即取消进行中的下载）。
