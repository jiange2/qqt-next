# App 移除后端策展播放列表与歌手入口

抽屉信息架构精简：下线「播放列表」页（后端管理员策展合集）与「音乐歌手」页（歌手网格）。策展合集在 App 内只读、无任何写入口，歌单心智已由本地歌单（ADR 0006）承担，两个"列表"概念并存只会互相污染；歌手网格连点击进入的下游路径都没有（歌手卡片不可点），歌手名仍随歌曲在列表与播放器中展示。后端 artists/playlists 接口与管理后台的维护能力保留，老版本 App 不受影响。

## Considered Options

- **保留播放列表页**：与本地歌单功能重叠且语义冲突（只读策展合集 vs 用户自建歌单）。否决。
- **仅摘入口、留代码**：模型、仓库方法与页面沦为死代码，易被误接回并拖累术语一致性（前有"多层移除删一半致编译错误"的教训）。否决。
- **入口与死代码一并移除（采纳）**：删 `Artist`/`Playlist` 模型、`getArtists`/`getPlaylists`/`getPlaylistSongs`、路由 `artist`/`playlist` 与对应页面；`home` 响应的 `latest_artist` 字段 App 端直接忽略。

## Consequences

- App 内唯一歌单概念是本地歌单（ADR 0006）；「播放列表」在 App 语言中降级为弃用词（见 CONTEXT.md 各词条 Avoid 注）。
- 后端与管理后台仍在维护策展播放列表与歌手，但 App 无消费入口；将来若要重新露出，属产品决策，需重立路由、页面与数据链路。
- 歌手名展示（歌曲列表行、播放器标题行、媒体通知）走 `Song.artist` 字符串字段，不受本次移除影响。
