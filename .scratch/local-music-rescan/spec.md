# 本地音乐扫描重做（MediaStore 系统媒体库）

Status: resolved

> 本 spec 取代 `.scratch/local-music/spec.md`（上一版本地音乐）中的「扫描与索引」部分，并推翻 ADR 0019 与 ADR 0021；元数据覆盖层（ADR 0020）、歌曲/专辑视图、播放接入等其余决策延续上一版。

## Problem Statement

上一版本地音乐用 SAF 目录授权加自研遍历：用户授权文件夹后，App 递归扫目录、逐文件算内容指纹、逐文件开解析器读标签。实际用起来是几千首歌首扫要等几分钟，界面只有一个「已扫描 N 个文件」的计数在爬；某些系统 provider 不给文件大小或修改时间时，增量失效退化成全量重读；选错目录、目录重叠被拒、授权被系统回收，任何一个都会让页面空掉或整页灰掉。同类播放器（椒盐音乐）打开就是全库列表——因为它们读的是系统媒体库，而不是自己当文件扫描器。用户要的是「打开就有的本地音乐」，不是「等扫描器干活」。

## Solution

把本地音乐的扫描来源换成 Android 系统媒体库（MediaStore）：用户授予一次标准的音频读取权限，本地音乐页直接查询系统早已索引好的音乐——毫秒级出全库，标题、艺术家、专辑、时长、音轨号、年份、专辑封面全部是系统预抽取的现成结果，`.nomedia`、隐藏文件、铃声明闹钟录音的过滤也由系统媒体扫描器天然完成。文件夹范围改为「全机音乐 + 排除文件夹黑名单」（对齐椒盐方式），排除开关即时生效、不需要重扫。扫描不再有进度条、不再需要取消——它只是一次查询。用户已有的元数据整理（覆盖层编辑）、歌曲/专辑两视图、离线播放等体验全部保留，只是歌曲身份从内容指纹换成媒体库的行 ID。

## User Stories

1. 作为本地音乐听众，我希望第一次进入本地音乐页时看到一句说明和「授权音乐访问」按钮，以便明白这个页面为什么需要权限。
2. 作为本地音乐听众，我希望授权走的是系统标准的音频权限弹窗，以便不必逐个文件夹去挑。
3. 作为本地音乐听众，我希望授权后立刻（秒级）看到全部本地音乐列表，以便像打开系统相册一样直接用。
4. 作为本地音乐听众，我希望在 Android 13+ 上授权的是「音乐」粒度的权限而不是整个文件系统，以便权限范围最小。
5. 作为本地音乐听众，我希望拒绝授权时页面给出解释和「去授权」入口，以便知道空列表是权限问题而不是没有歌。
6. 作为本地音乐听众，我希望权限在系统设置里被撤销后再进页面时，看到重新授权引导和灰显的旧列表，以便知道歌没丢、只是权限没了。
7. 作为本地音乐听众，我希望所有音乐自动出现在列表里、不需要先选中任何文件夹，以便零配置开听。
8. 作为本地音乐听众，我希望铃声明、闹钟、通知音、录音、播客不进列表，以便列表里只有真正的音乐。
9. 作为本地音乐听众，我希望 `.nomedia` 目录里的音频和隐藏文件不进列表，以便行为与系统相册一致。
10. 作为本地音乐听众，我希望插入 SD 卡后卡里的音乐也出现在列表，以便不漏掉外置存储。
11. 作为本地音乐听众，我希望顶栏菜单可以打开「排除的文件夹」，以便不想让某些目录（如杂乱下载目录）出现在列表里。
12. 作为本地音乐听众，我希望排除清单自动列出当前库中所有含音乐的文件夹并带开关，以便直接勾选、不用手输路径。
13. 作为本地音乐听众，我希望排除某个文件夹时它的子文件夹一并被排除，以便一次排除整个目录树。
14. 作为本地音乐听众，我希望切换排除开关后列表立即生效、不需要重新扫描，以便所见即所得。
15. 作为本地音乐听众，我希望排除状态在重启后仍然生效，以便不用每次重新勾。
16. 作为本地音乐听众，我希望进入页面时库被静默刷新一次，以便在外部增删文件后回到 App 就是新状态。
17. 作为本地音乐听众，我希望顶栏「重新扫描」完成后提示新增与移除的数量，以便知道这次刷新改变了什么。
18. 作为本地音乐听众，我希望刷新期间界面不出进度条、也不需要取消，以便不被无意义的等待打断。
19. 作为本地音乐听众，我希望在「歌曲」视图看到全部本地歌曲并按标题中文排序，以便浏览和点播。
20. 作为本地音乐听众，我希望在「专辑」视图看到按专辑归并的卡片墙，以便按专辑找歌。
21. 作为本地音乐听众，我希望点开专辑看到整张专辑的歌曲并整单播放，以便按专辑顺序聆听。
22. 作为本地音乐听众，我希望文件缺标题标签时以文件名兜底，以便不看到空白行。
23. 作为本地音乐听众，我希望文件缺专辑标签时以所在文件夹名兜底成组，以便散装文件也能进专辑视图。
24. 作为本地音乐听众，我希望同曲目的多个副本各自显示一行，以便知道文件确实有重复（跟随媒体库事实，App 不做内容级去重）。
25. 作为本地音乐听众，我希望点击歌曲时以当前列表整体作为播放队列，以便连续播放。
26. 作为本地音乐听众，我希望本地音乐的播放模式单独记忆，以便随机模式不影响在线专辑。
27. 作为本地音乐听众，我希望重启 App 后恢复本地播放队列与进度，以便中断后接着听。
28. 作为本地音乐听众，我希望长按歌曲行打开编辑面板修改标题、艺术家、专辑、专辑艺术家、音轨号、年份，以便整理标签混乱的文件。
29. 作为本地音乐听众，我希望全屏播放器的「更多菜单」里也有「编辑信息」（仅本地歌曲出现），以便边听边改。
30. 作为本地音乐听众，我希望编辑结果在重新扫描后仍然生效，以便整理不白费。
31. 作为本地音乐听众，我希望可以一键恢复某首歌的默认标签，以便改错后回退。
32. 作为本地音乐听众，我希望修改专辑信息后歌曲立即换到对应专辑分组，以便所见即所得。
33. 作为本地音乐听众，我希望专辑封面来自系统媒体库预抽取的专辑图，以便专辑墙有封面且加载快。
34. 作为本地音乐听众，我希望没有专辑图的专辑显示占位图，以便界面整齐。
35. 作为本地音乐听众，我希望正在播放时刷新库不打断播放，以便随便刷新。
36. 作为本地音乐听众，我希望播放中文件被删除时该行灰显并提示、下次刷新后消失，以便理解发生了什么。
37. 作为本地音乐听众，我希望本地音乐完全离线可用、不发任何网络请求，以便飞行模式下照样浏览和播放。
38. 作为本地音乐听众，我希望本地歌曲不出现收藏、加入歌单、评分、下载和歌词入口，以便不点到注定失败的功能。

## Implementation Decisions

### 扫描来源与权限（推翻 ADR 0019）

- 扫描来源改为系统媒体库：持有音频读取权限时查询 `MediaStore.Audio.Media`，条件 `IS_MUSIC != 0`（天然排除铃声、闹钟、通知、录音、播客），Android 10+ 附加 `IS_PENDING = 0`，Android 11+ 附加 `IS_TRASHED = 0`。不再使用 SAF、不再有目录授权、不再有目录树遍历。
- 权限模型：Android 13+ 申请 `READ_MEDIA_AUDIO`，Android 12 及以下申请 `READ_EXTERNAL_STORAGE`（清单中后者标 maxSdkVersion 32）。拒绝 → 解释空态 + 重试/去系统设置入口；撤销 → 进页面权限检查失败 → 保留快照并灰显 + 重新授权横幅。
- 多存储卷：Android 10+ 用 `MediaStore.getExternalVolumeNames` 逐外置卷查询合并（机身存储 + SD 卡）；Android 9 及以下只查主外置卷集合。外置 USB OTG 上媒体库不索引的音频扫不到——系统边界，与椒盐一致，不做 SAF 补充。
- 删除格式白名单、点开头隐藏文件、`.nomedia` 目录规则：哪些音频入库由系统媒体扫描器决定，App 不再重复判断。

### 接缝

- 唯一新接缝 `LocalMusicLibrarySource`：权限检查 + 按卷查询 + 行归一化，返回「归一化歌曲行」（行 ID、卷名、路径、文件名、大小、修改时间、时长、标签字段、专辑 ID）。它下游的排除过滤、覆盖层合并、专辑分组、排序、快照持久化是一条纯 Kotlin 管线（这正是上一版 spec 预留的最高接缝，注入边从「SAF + 标签读取」换成「MediaStore 查询」）。UI 与 ViewModel 的既有接缝不动。

### 身份（推翻 ADR 0021）

- 歌曲身份 = MediaStore 行 ID，Android 10+ 带卷名限定防止跨卷撞号；`local:` 播放命名空间与本地歌曲判据不变，ID 值从指纹十六进制换成行 ID。
- 内容指纹、首尾 SHA-256、「路径+大小+修改时间」增量跳过逻辑全部删除。同一内容的多个副本各自成行显示——放弃内容级去重，覆盖上一版的对应 story。
- 升级迁移：旧索引按指纹记身份、旧覆盖层按指纹记键，与新身份对不上；升级后首次启动直接丢弃旧快照与旧覆盖层（覆盖层数据量小、重编辑成本低），旧 SAF 授权残留不清理也不使用。
- 覆盖层（ADR 0020）继续独立文件、原子写、只存非空值，键改为行 ID。文件被删除重加（行 ID 变化）后编辑丢失——已知取舍。

### 库快照与刷新

- 「扫描索引」文件改为「库快照」：歌曲行 + 排除清单，启动在 IO 线程读取，冷启动直接出列表；不再有「有授权没索引就自动开扫」「从持久化授权重建目录」的分支。
- 进入页面（以及授权成功后）静默刷新一次：整库重查（毫秒级）→ 按身份 diff → 合并覆盖层 → 提交；顶栏「重新扫描」走同一管线，完成后提示「新增 x、移除 y」，静默刷新不提示。
- 扫描进度、扫描取消、原子提交等待态全部删除：查询即事实；快照照旧原子写（临时文件 + rename）。
- 排除过滤发生在查询结果的内存管线里，切换排除开关只重过滤、不重扫。

### 文件夹黑名单（对齐椒盐）

- 排除清单是一组文件夹路径，匹配语义为「该文件夹及其全部子文件夹」。可选文件夹清单从库行的路径派生（Android 10+ 取 `RELATIVE_PATH`，低版本从 `DATA` 的目录段），展示名用目录名/`BUCKET_DISPLAY_NAME`。
- 排除状态随快照落盘；被排除的行不进歌曲列表、不进专辑分组、不进播放队列候选。

### 专辑与封面

- 专辑分组键保持「专辑名 + 专辑艺术家」的合并展示值（沿用现有排序与编辑换组语义，中文 `Collator`）。专辑艺术家字段 Android 11+ 取 `ALBUM_ARTIST` 列，低版本为空、走现有兜底路径。
- 封面 = 按专辑成员行的 `ALBUM_ID` 取系统预抽取的专辑图（Albums 表 `ALBUM_ART` / albumart URI），由图片加载器直接加载与缓存；删除文件夹封面扫描与自管 LRU 封面文件缓存。无图专辑显示占位图。文件夹里的 `cover.jpg` 类封面文件不再使用。
- 音轨号取 `TRACK` 列（多碟专辑的碟位编码按 Android 惯例解出音轨号）、年份取 `YEAR`、时长取 `DURATION`。本地音乐链路中不再出现 `MediaMetadataRetriever`。

### 播放与失效

- 队列元素 URL = 按卷 + 行 ID 构造的 content URI；播放兼容层、按来源记忆播放模式（ADR 0015 的 `local` 键）、队列快照恢复、离线判据全部沿用。
- 播放中文件被删：维持「该行灰显 + 提示」，下次刷新后自然消失（媒体库里已无此行）；权限被撤销：快照灰显 + 重新授权横幅，不放空列表假装没歌。

### 文档

- 新增 ADR 0022（扫描来源改为 MediaStore 系统媒体库 + 音频权限 + 文件夹黑名单），声明推翻 ADR 0019 与 ADR 0021；ADR 0020 覆盖层继续有效。
- 同步 Android 存储与 UI 说明文档；CONTEXT.md 词条补充「排除文件夹」，修订「本地音乐」的来源描述（授权文件夹 → 系统媒体库）。

## Testing Decisions

- 好的测试只测外部行为：给接缝喂归一化行、断言列表/专辑/提示的最终形态，不测内部排序实现。
- 接缝：`LocalMusicLibrarySource` 之下的整条管线（黑名单过滤、覆盖合并、专辑分组、排序、新增/移除 diff）为纯 Kotlin，未来 JVM 单测的注入点就在这一个接口上（伪造行列表即可）；SAF 遍历时代的仪器测试不再需要。
- 本仓现状维持手工验收（与上一版一致），清单覆盖：首启授权 → 秒出全库；拒绝/撤销授权 → 引导与灰显恢复；排除开关即时生效（含子文件夹、重启保留）；重扫提示新增/移除数；无标签兜底文件名与文件夹；编辑跨重扫保留、改专辑即时换组；无封面专辑占位图；飞行模式全功能；播放器内本地歌无网络入口；播放中删文件 → 灰显 → 刷新消失。

## Out of Scope

- 椒盐的「指定文件夹扫描」第二模式（白名单目录遍历）。
- 外置 USB OTG 上媒体库不索引的音频。
- 文件内容指纹与内容级去重、把标签写回音频文件、批量编辑。
- 文件夹浏览视图（层次/平铺）、本地音乐内搜索、排序菜单、多选拖拽。
- M3U 等歌单文件导入导出、本地歌词。
- 本地歌曲进入收藏、我的歌单、评分、下载。
- 监听媒体库变更通知做后台自动刷新（媒体库增量由系统维护，进页面静默刷新已够）。

## Further Notes

- 列可用性已用 javap 对着 compileSdk 35 的 android.jar 核过：`IS_MUSIC`/`ALBUM_ID`/`TRACK`/`YEAR` 在 AudioColumns（API 1 起全程可用）；`ALBUM_ARTIST`/`IS_TRASHED` 为 30+，`IS_PENDING`/`RELATIVE_PATH`/`BUCKET_DISPLAY_NAME` 为 29+，低版本条件读取；`Albums.ALBUM_ART` 与 `getExternalVolumeNames`（29+）如文中所说按版本取用。
- 椒盐参考来源是其官方介绍页（系统媒体库 + 指定文件夹 + 黑名单）、Google Play 描述（增量扫描 + 文件夹黑名单）与 issue #1769（外置 USB 不识别即 MediaStore 边界）。该仓库无 App 源码，参考的是机制与产品行为，不是代码。
- 首扫成本从「每文件一次指纹 IO + 一次标签解析」降为一次数据库查询；扫描在本地音乐链路中的存在感归零。
- 本地音乐与「下载列表」仍是两个互不包含的集合；「响应快照」「服务器不可达」等网络降级机制不受影响——本地音乐页照旧零网络请求。
