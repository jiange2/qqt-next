# 本地音乐编辑候选（专辑 / 艺术家 / 专辑艺术家下拉）

Status: resolved

> 延续 ADR 0020（元数据只写 App 内覆盖层、不回写文件标签）与 ADR 0022（MediaStore 来源、行 ID 身份），不推翻任何 ADR。基线含已归档的批量管理特性（main ee4c5ee：单首 / 批量面板共用 `MetadataField` 自由文本）。本特性只给既有编辑字段加候选，不改任何保存语义。

## Problem Statement

单首「编辑信息」面板与批量管理面板的专辑、艺术家、专辑艺术家都是纯手输。把散落的歌归并进一张已有专辑、或把错别字改成库里已有的正确写法，要凭记忆逐字敲全名；敲错一个字就归并进一张新的同名专辑。用户需要：编辑这些字段时，按本地库里已有的专辑和艺术家给出下拉候选，点选即填。

## Solution

两个面板的专辑类 / 艺术家类字段换成「可手输 + 内联候选列表」控件：聚焦即展开本地库当前值派生的候选，打字即过滤，点选即回填；专辑候选点选时连带回填专辑艺术家框（单首、批量同规则），让批量改专辑真正归并进同一张。候选只取本地库（覆盖层合并后的展示值），不混入在线实体。自由输入保留——库里没有的新名字照样能填。保存语义一字不改：单首「留空 = 恢复文件原值」、批量「填了的字段才改、留空保持原样」，只写覆盖层、不动音频文件。

## User Stories

1. 作为本地音乐听众，我在单首编辑面板点「艺术家」「专辑」「专辑艺术家」任一框，看到库里已有值的候选列表，以便点选而不是手敲。
2. 作为本地音乐听众，我在批量管理面板点「专辑」「专辑艺术家」框，同样看到候选，以便把选中的歌归并进已有专辑。
3. 作为本地音乐听众，我打字时候选按输入即时过滤（专辑名或专辑艺术家包含即命中，忽略大小写），以便快速定位。
4. 作为本地音乐听众，我点选一条专辑候选后专辑框与专辑艺术家框一起填好，以便批量保存后选中的歌并进同一张专辑（归并键 = 专辑名 + 专辑艺术家）。
5. 作为本地音乐听众，我点选艺术家 / 专辑艺术家候选只填本框，不连带其他字段。
6. 作为本地音乐听众，我仍能输入候选里没有的新名字并保存，以便纠正成库里还没有的正确值。
7. 作为本地音乐听众，我保存后面板关闭、列表与专辑分组即时刷新，再次打开编辑时候选已是最新值（含刚改过的）。
8. 作为本地音乐听众，我在空库或字段无已有值时看到的就是普通输入框（无候选列表），以便不被空列表打扰。
9. 作为本地音乐听众，我看到候选行带次文本（专辑候选显示专辑艺术家），同名不同艺术家的专辑能区分着选。

## Implementation Decisions

### 候选池（数据层，纯函数）

- 新文件 `data/local/LocalMetadataSuggestions.kt`：`MetadataSuggestion(value, supporting?)` + 三个派生函数 + 过滤函数，全部从 `List<LocalSong>` 当前展示值派生（覆盖层优先），不新增查询、不碰在线实体。
- **专辑候选** `albumSuggestions()`：复用 `groupIntoAlbums()`，**只收有真实专辑标签的组**（首成员 `displayAlbum()` 非空），每行 `value` = 专辑名、`supporting` = 专辑艺术家（`LocalAlbum.artist` 卡片口径：专辑艺术家优先、缺失回退该专辑按音轨序第一首的艺术家）；按展示对去重；排序沿用 `groupIntoAlbums()` 的中文序（专辑名升序、同名按艺术家）。
  - **文件夹兜底专辑排除**：专辑名为空、按文件夹名展示的组不进候选——改标签无法归并进文件夹组（文件夹组要求专辑标签为空，写入专辑名只会造出一张同名平行的专辑键组），候选只收「点选后能真正归并进去」的专辑。
- **艺术家候选** `artistSuggestions()`：`displayArtist()` 非空去重，中文序（`Collator` `Locale.CHINA`，每次调用新建，与 `groupIntoAlbums()` 同范式）。
- **专辑艺术家候选** `albumArtistSuggestions()`：`displayAlbumArtist()` 与 `displayArtist()` 的并集非空去重，中文序——专辑艺术家标签常缺失（该列 API 30+ 才有值），卡片展示本就回退艺术家，候选池同口径。
- **过滤** `filterSuggestions(query)`：query trim 后为空 → 全量；否则 `value` 或 `supporting` 包含（忽略大小写）即命中。
- 候选来源流：单首面板在面板内 `viewModel.songs.collectAsState()` + `remember(songs)` 派生；批量面板由导航层从既有 `localMusicSongs`（已按排除清单过滤的可见列表）派生后作参数传入，面板保持无 ViewModel 的展示组件形态。本地音乐页与专辑页（票据04）两处批量面板调用共用同一份派生——专辑页批量也是把歌归并进库里任何一张已有专辑，候选取整库、不限于当前专辑。

### 控件与交互（UI 层）

- 新控件 `ui/screens/localmusic/MetadataSuggestionField.kt`（internal）：`OutlinedTextField` 同款描边 / 配色（BrandOrange 焦点色）+ 尾部 `ArrowDropDown` 图标（展开时旋转 180°、变 BrandOrange）+ 字段下方**内联展开候选列表**。标题 / 音轨号 / 年份仍用原 `MetadataField`。
- **不用 Popup 下拉**（机制报备）：ModalBottomSheet + 软键盘场景下 Popup 定位与 IME 遮挡风险高且无法真机回归；内联列表随面板滚动、始终在 `imePadding` 之上，矮屏可滚到。
- 展开 / 收起：字段**聚焦即展开全量**（不按预填值过滤——单首面板初值是当前值，聚焦是为了换值不是搜当前值）；失焦自动收起；打字即按输入过滤并展开；过滤后无匹配 → 列表收起（输入框照常手输）。尾部图标点击切换展开：收起 → 展开时清过滤、显示全量并请求焦点。同一时刻只有一个字段持有焦点，故至多一个列表展开。
- 点选候选：回填本框（专辑候选连带回填专辑艺术家框，见下），收起列表并 `clearFocus()`（收键盘）。
- 列表形态：`PlaceholderBg` 淡底圆角容器，`heightIn(max = 220.dp)` 内滚；每行主文本 13sp InkPrimary + 次文本 11sp InkSecondary（单行省略）；**最多渲染 50 行**，超出显示「还有 N 项，输入关键字过滤」提示行（防大库全量组合卡顿，纯 Column 非 Lazy——LazyColumn 在 heightIn(max) 下会撑满最大高度）。
- 空候选（空库 / 无标签 / 过滤无匹配）不渲染列表，字段退化为纯手输，与现状一致。

### 专辑候选联动（单首、批量同规则）

- 点选专辑候选 → 专辑框 = `value`，专辑艺术家框 = `supporting.orEmpty()`。批量面板两框皆非空 → 选中行全部按同一「专辑名 + 专辑艺术家」落组，真正并进一张。
- 纯手输不联动；批量点选后手动清空专辑艺术家框 = 不改该字段（既有语义），可能按各自原专辑艺术家拆组（批量 spec 既有口径，不变）。
- 单首面板「留空 = 恢复文件原值」、批量「留空 = 不改」、保存禁用条件、trim、覆盖层生成规则全部不变——联动只是替用户填框，提交链路零改动。

### 文档

- CONTEXT.md 无新增词条：grilling 已把「作者」对齐到现有规范词「艺术家」「专辑艺术家」（「专辑作者」已在弃用词），候选下拉是 UI 机制不是领域术语。
- `android/doc/ui.md`：LocalMetadataEditSheet 节补候选下拉（三字段、内联列表、聚焦展开 / 打字过滤 / 点选联动、50 行上限）；批量变体条目同步；目录行补 `MetadataSuggestionField`。
- 不新增 ADR：可逆的 UI 扩展（沿 ADR 0020 / 0022，保存语义零改动）；文件夹专辑排除与联动边界记入本 spec Further Notes，三条门槛（难以反转 / 无上下文会让人惊讶 / 真实取舍）均不成立。

## Testing Decisions

- 纯函数 JVM 测试 `LocalMetadataSuggestionsTest`：专辑候选（真实专辑归并一行、文件夹兜底排除、覆盖值优先、专辑艺术家缺失回退第一首艺术家、同名不同艺术家两行、展示相同去重、中文排序）、艺术家候选（去重、空值排除、覆盖优先）、专辑艺术家候选（并集去重）、过滤（空 / 空白查询全量、忽略大小写、次文本命中、无匹配、trim）、空库三函数皆空。断言用独立字面量。本仓规约：AI 不编译、不跑 gradlew，测试照写待人工执行。
- 设备级验收清单（人工）：单首三字段聚焦展开 / 打字过滤 / 点选回填 / 专辑联动；批量两字段同规则；键盘弹出时列表可见可滚；失焦 / 尾部图标收起；空库无列表；保存后再开候选已更新；恢复默认后候选回退；手输新值保存不受影响。

## Out of Scope

- 在线艺术家 / 专辑实体混入候选（本地标签与在线实体是两套数据）。
- 标题 / 音轨号 / 年份候选（无既有值集合可言）。
- 批量改其他字段、批量删除（批量管理 spec 边界不变）。
- 写回文件标签（ADR 0020 不变）。
- 候选跨设备 / 云端来源、候选记忆或手工维护。
- 专辑卡片墙整张勾选；本地专辑页编辑模式本身（批量管理票据04 范围，本特性只为其批量面板接候选，边界以票据04 为准）。

## Further Notes

- **专辑艺术家为空的专辑的已知边界**：候选次文本是回退艺术家（卡片展示值）。点选写入该值后，被改的歌归入「专辑名 + 回退艺术家」组；若只改该专辑的**部分**歌，会与未改的歌（专辑艺术家仍为空）拆成两张同名卡——这是归并键既有口径的结果（手输同样如此），不是新语义；整张全选改完则并成一张。
- 文件夹兜底专辑不可通过改标签归并（文件夹组要求专辑标签为空），故不进候选；排除判据用首成员 `displayAlbum()` 非空，不耦合专辑键字符串格式。
- 候选随 `songs` 流即时重算：编辑保存、恢复默认、重扫、排除文件夹切换后候选自动更新；派生用 `remember(songs)`  memoize，不在每帧重组。
- 两个入口（本地音乐页歌曲视图长按、本地专辑页长按）共用单首面板，自动同享候选。播放器侧编辑接线已由「本地播放器图标行移除」特性拆除（main e39607f），本地歌曲编辑只走列表长按，无第三入口。
- 基线工作树含在途的专辑页批量管理（票据04，未提交：`batchAlbumNewKeys` 跟随导航）：同一 `LocalBatchEditSheet` 的第二处调用，候选同享。点选专辑候选且次文本非空时两框皆填 → 选中行落同一新键，`batchAlbumNewKeys` 必为单键，跟随导航直达新专辑；次文本为空（专辑艺术家缺失且艺术家也空）时只填专辑名，仍按既有口径可能拆组。
- grilling 一轮定稿（2026-11-14）：Q1–Q5 全部同意——两个面板都加、「作者」对齐为艺术家 / 专辑艺术家两类框、保留手输、专辑候选点选联动填专辑艺术家、候选只取本地库当前值。机制委托项（内联列表而非 Popup、候选池口径、文件夹专辑排除、50 行上限、聚焦展开全量 / 打字过滤）随实现报备。
