# CDN 看板（cdn-dash）

Status: ready-for-agent

> 新上下文，与音乐业务无数据往来（见根目录 `GLOSSARY-MAP.md`）。遵循 ADR 0015（端上直连、每账号只读 AK、Keystore 加密）、ADR 0016（账号全量口径）、ADR 0017（账期口径、不摊销），三者均在 `docs/adr/`。术语一律用 `cdn-dash/GLOSSARY.md`。

## Problem Statement

使用者名下有多个阿里云账号，每个账号都开着 CDN。想知道「今天用了多少流量」「最近一周走势如何」「买的流量包还剩多少、什么时候到期」「这一年到底花了多少钱」，现在只能在电脑上分别登录每个账号的控制台，逐个点开 CDN 概览、资源包、费用中心，并且流量、余量、花费分散在三个页面，无法横向对比账号。手机上没有一个能一屏看完的入口。

## Solution

一个独立的 Android 应用：在设置里录入多个阿里云账号的只读 AccessKey（加密存在本机），打开即可看到所有账号的今日累计、最近 7 天走势与资源包余量；顶部汇总「所有账号今日累计」与「所有账号最近 7 天总量」；第二个页面看每个账号近 12 个月的账号花费。数据由 App 直连阿里云 OpenAPI 取回，无自建后端、无本地历史库、离线时展示上次成功获取的快照并标注数据时间。

## User Stories

1. 作为多账号运营者，我希望在设置里新增一个阿里云账号（名称 + AccessKeyId + AccessKeySecret），以便把要看的账号都纳进来。
2. 作为多账号运营者，我希望账号名称可以自己起（如「主站生产」「海外测试」），以便一眼认出是谁。
3. 作为多账号运营者，我希望录入的密钥只存在本机且加密保存，以便手机被他人拿到时不至于直接读走秘钥。
4. 作为多账号运营者，我希望删除账号时它的密钥被一并清除，以便不再需要时不留残留。
5. 作为多账号运营者，我希望可以启用/停用某个账号，以便临时不看某账号但不必删掉配置。
6. 作为多账号运营者，我希望可以拖拽调整账号顺序，以便把最关心的账号排在前面。
7. 作为多账号运营者，我希望列表顺序不因流量大小自动变化，以便「某个账号突然涨了」不会被位置变化掩盖。
8. 作为多账号运营者，我希望打开应用就看到所有账号合计的今日累计，以便快速知道今天整体用了多少。
9. 作为多账号运营者，我希望今日累计旁标注「截至 HH:mm」，以便知道这是半日数据、不是一整天。
10. 作为多账号运营者，我希望同时看到所有账号合计的最近 7 天总量，以便对整体量级有概念。
11. 作为多账号运营者，我希望最近 7 天不包含今天，以便半日数据不污染周总量。
12. 作为多账号运营者，我希望每个账号一张卡片，卡内显示今日累计、7 天合计与 7 天走势折线，以便按账号下钻。
13. 作为多账号运营者，我希望折线是按天的一个点一个点，以便一眼看出哪一天高、哪一天低。
14. 作为多账号运营者，我希望折线的日界固定为北京时间，以便和阿里云账单对得上、出差换时区也不变。
15. 作为多账号运营者，我希望卡片上看到资源包剩余量的摘要，以便不用点进去就知道还剩多少。
16. 作为多账号运营者，我希望资源包按区域分开、区域内按到期日从小到大排列，以便知道哪个包最先用完失效。
17. 作为多账号运营者，我希望同一个到期日、同一区域的多个包合并成一行并显示包数，以便列表不被几十个包淹没。
18. 作为多账号运营者，我希望看到已到期或已耗尽之外的「尚未生效」的包并明确标注，以便知道刚买的包什么时候开始抵扣。
19. 作为多账号运营者，我希望只统计 CDN 流量包、不混入全站加速或 OSS 的包，以便「CDN 还能撑多久」不被别的产品稀释。
20. 作为多账号运营者，我希望点账号卡片能看到资源包明细列表，以便核对单个包的余量与到期日。
21. 作为多账号运营者，我希望看到每个账号近 12 个月的花费柱状与全年合计，以便判断成本趋势。
22. 作为多账号运营者，我希望花费是整账号所有产品的合计，而不只是 CDN，以便知道这个账号总共花了多少。
23. 作为多账号运营者，我希望买流量包的那个月被标注「含预付费资源包」，以便不把尖峰误读为超支。
24. 作为多账号运营者，我希望花费只显示已出账的完整月份，以便数字和账单一致、不被当月估算误导。
25. 作为多账号运营者，我希望能看到每月花费里现金与代金券各多少，以便知道真实支出结构。
26. 作为多账号运营者，我希望某个账号的密钥失效时只有它自己显示「凭证失效」，其他账号照常出数，以便一个坏配置不拖垮整页。
27. 作为多账号运营者，我希望顶部汇总在部分账号失败时标注「N 个账号数据缺失」，以便知道合计不是全量。
28. 作为多账号运营者，我希望某个账号没有费用接口权限时，只在该页提示「费用权限未开启」，以便知道该补哪个权限而不是以为坏了。
29. 作为多账号运营者，我希望打开应用与下拉时自动刷新，并每 5 分钟自动更新一次，以便数字不至于太旧。
30. 作为多账号运营者，我希望退到后台后不再请求，以便不白耗电量与接口配额。
31. 作为多账号运营者，我希望断网时仍能看到上次的数据并标明抓取时间，以便在弱网环境下不面对一片空白。
32. 作为多账号运营者，我希望花费页单独按需加载并缓存，以便首屏不会因为 12 个月的账单请求而变慢。
33. 作为多账号运营者，我希望可以设置是否开启生物识别解锁，以便手机被借走时多一层阻挡（默认关闭）。
34. 作为多账号运营者，我希望账号卡片上的错误能说清是密钥错、权限不足还是网络问题，以便我知道该去控制台改什么。
35. 作为多账号运营者，我希望没有任何账号时看到明确的引导（去设置添加账号），以便知道从哪开始。
36. 作为多账号运营者，我希望看到每个资源包按最近 7 天区域日均还能用多少天、预计哪天用完，以便在包到期前决定要不要补量。

## Implementation Decisions

### 工程与依赖

- 新目录下的独立 Gradle 工程，与既有音乐客户端工程互不引用、互不依赖；语言 Kotlin，UI 用 Jetpack Compose（Material 3），导航用 Navigation Compose，序列化用 kotlinx.serialization，HTTP 用 OkHttp，本地键值用 DataStore。
- 不引入阿里云官方 SDK（RPC v1 签名手写，沿用既有服务端实现的算法）；不引入图表库（折线、柱状用 Canvas 自绘）；不引入 `androidx.security:security-crypto`（自行用 Keystore AES-GCM 加密，理由见 ADR 0015）。
- 字节一律按 1024 进制格式化；金额保留两位小数；时区常量固定 `Asia/Shanghai`，不读取设备时区。

### 数据口径与接口契约

- **今日累计**：`DescribeDomainTrafficData`，不传 `DomainName`（账号全量），`Interval=300`，时间窗为北京时间今天 00:00 至请求时刻；结果为字节数，标记为未结算。
- **7 天走势与总量**：同一接口，`Interval=3600`，时间窗为北京时间「今天-7」00:00 至「今天」00:00；端上按北京自然日汇总为 7 个点，丢弃任何落在今天的点。折线按天渲染，但数据不依赖日粒度接口（日粒度延迟 4–24 小时，昨日可能半截）。
- **资源包余量**：CDN `DescribeCdnUserResourcePackage` 与 DCDN `DescribeDcdnUserResourcePackage` 双端点合并（新版 CDN 资源包是 CDN/全站加速共享商品 `dcdnpaybag`，可能只出现在 DCDN 端点），按 `InstanceId` 去重；每端点查两轮：默认（valid）+ `Status=exhaust`，两轮都成功才算端点成功。接口没有到期时间参数，只能事后过滤：客户端按到期时间只保留未来到期的包（缺失到期时间按未知保留）；用完的包不单独剔除，合并分组后整组剩余量为 0 的组隐藏——已耗尽包必须补查，否则同组总量会少算。容量字段兼容千分位逗号。只接受 `CommodityCode` 为 `cdnflowbag`/`dcdnpaybag` 的条目，`dcdnpaybag` 再按容量单位（Byte）排除 HTTPS 请求数包；CDN 为主端点（失败即整体失败），DCDN 为补充端点（失败容忍）。按（区域，到期日）分组，组内求和剩余量与总量并计数包数，按到期日升序；未生效（生效时间晚于当前）的组需要可识别标注。区域之间不合并、不相加。
- **预计可用天数**：按（区域，到期日）组计算「该组可用余量 ÷ 该区域最近 7 天日均」，区域之间不相加（GLOSSARY「区域日均」「预计可用天数」）。日均来自 7 天响应的 `DomesticValue`/`OverseasValue` 区域拆分，与总量同一次请求，**看板不新增请求**。未生效、区域未知、7 天来自没有区域字段的旧快照时静默不估算；本区域 7 天合计为 0 时显示「近 7 天无流量，暂不估算」。判定顺序：先用**未取整**的原始天数与到期时刻比较（原始天数 ≥ 剩余到期天数 → 「到期前用不完」，避免 5.7 天被四舍五入成 6 天后误判），再取整展示：不足 0.5 天 → 「不足 1 天」，超过 999 天 → 「>999 天」。明细页的预计用完日按北京自然日显示 `MM-dd`；7 天来自离线快照时只给天数、不给日期（ADR 0018）。
- **账号花费**：`QueryAccountBill`，每账号 12 次，`Granularity=MONTHLY`，逐个完整的自然月（剔除当月）；主数取 `PretaxAmount`，明细取 `CashAmount` 与代金券字段；不按产品过滤。无税额字段，界面不出现「含税」字样。
- **认证与签名**：RPC v1（HMAC-SHA1），公共参数含 `Action`/`Version`/`Format`/`AccessKeyId`/`SignatureMethod`/`SignatureVersion`/`SignatureNonce`/`Timestamp`；`Timestamp` 用 UTC；`SignatureNonce` 每次请求唯一；请求与响应均有超时上限。
- **错误归一**：鉴权类（密钥无效、签名错误）→ 该账号「凭证失效」；权限类（无 CDN/BSS 读权限）→ 该账号对应模块「权限不足」；限流类（`Throttling`）→ 指数退避重试有限次后按网络错误处理；网络/超时 → 该账号「网络错误」。任何单账号错误都不得使其他账号或整页失败。

### 模块与接缝

- **唯一网络接缝 `AliyunApi`**：以账号与时间窗为入参、以领域对象（日流量点集合、资源包条目、月账单）为出参；实现内含签名、HTTP、解析与错误归一。所有 UI 与 ViewModel 只依赖该接口，不直接拼参数、不直接解析 JSON。
- **唯一持久化接缝 `AccountStore`**：负责账号元数据（名称、是否启用、排序、密钥密文）与快照缓存（各模块最近一次成功的领域结果 + 抓取时间）的读写；密钥的加解密藏在其内部，调用方只传明文、不接触密文。
- **纯函数**：按北京自然日聚合小时点为日点（含区域拆分）、丢弃今天、求 7 天合计；按（区域，到期日）分组资源包；按区域日均估算资源包可用天数与到期比较；顶部汇总（今日累计与 7 天总量，排除停用与失败账号并给出缺失计数）；字节与金额格式化。这些都是无状态函数，不通过接口注入。
- **刷新编排**：打开、下拉、前台每 5 分钟各触发一次「读账号列表 → 并发取数（账号内串行、账号间有上限）→ 更新快照 → 聚合 → 渲染」；退到后台取消定时器；花费页独立触发、结果缓存 24 小时。
- **密钥落盘**：Keystore 中生成不可导出的 AES-GCM 密钥，密文以 base64 存入 DataStore；密钥不进日志、不进备份、不导出；删除账号同时删除密文与快照。
- **生物识别开关**：默认关闭；开启后进入应用前要求一次生物识别；失败可回退到设备凭据；该开关的失败不得阻碍正常使用（设备不支持时隐藏并说明）。

### 页面结构

- **看板页**：顶部两数（所有账号今日累计 / 所有账号最近 7 天总量，各带口径小字与缺失标注）→ 账号卡片列表（账号名、今日累计、7 天合计、7 点折线、资源包余量摘要、错误状态）→ 点卡片进入该账号资源包明细页。资源包摘要每行在包数/未生效之外追加「约可用 N 天」等短标签；只要存在可估算的组，区块显示一次「天数按区域近 7 天日均估算」。
- **资源包明细页**：按区域分组、组内按到期日升序，每行显示到期日、包数、剩余量、总量、是否未生效，以及「约可用 N 天 · 预计 MM-dd 用完」；页面顶部在同一条口径说明处追加估算依据。
- **花费页**：账号切换 + 12 根月柱 + 全年合计；含预付费的月份需标注；无权限账号显示可操作提示。
- **设置页**：账号增（名称/密钥）、删、启用停用、拖拽排序、刷新间隔、生物识别开关、关于。

## Testing Decisions

- 好的测试只断言外部行为：给定账号、时间窗与接口响应，断言渲染所依赖的领域结果（日点、合计、分组、错误状态），不断言内部实现（不测签名中间字符串、不测 ViewModel 私有状态、不测 Compose 布局细节）。
- 网络接缝 `AliyunApi` 用 MockWebServer 在 HTTP 层验证：请求含正确公共参数与业务参数、签名可被同样算法复原、响应解析为领域对象、四类错误被归一为对应状态。
- 持久化接缝 `AccountStore` 用内存实现替换，验证「保存后读回一致」「删除后密文不存在」「快照带抓取时间」；Keystore 的真实加解密依赖设备，留真机验收。
- 纯函数用 JVM 测试并以字面量断言：跨北京日边界（23:55 与 00:05 落在不同天）、跨时区设备仍按北京日、今天被丢弃、7 点数量恒定、空数据显示全零而非崩溃、资源包按（区域，到期日）分组与升序、未生效标注、区域不相加、区域拆分按日求和、区域日均分母恒 7、未知区域/旧快照无区域字段静默、零流量、不足 1 天、>999 天、到期比较用未取整天数、北京自然日推算用完日、旧快照编解码兼容、顶部汇总排除停用与失败并给出缺失计数、1024 进制格式化边界（B/KB/MB/GB/TB）。
- 先例：仓内 `LocalMusicDeleterTest` / `LocalDeleteRulesTest` 的写法（纯函数 + 结果归一，字面量断言，不依赖 Android 框架）。
- 沿用本仓惯例：测试写好但不代为编译执行；设备级行为（Keystore、生物识别、真实 OpenAPI 返回）列入人工验收清单。

## Out of Scope

- 自建后端、STS 签发、跨账号 AssumeRole。
- 实时带宽/网速曲线（已明确只要今日累计）。
- 阈值告警、推送、异常检测、带宽封顶。
- 全站加速（DCDN）流量统计、OSS 流量包与回源流量。
- 按域名拆分流量、按域名筛选。
- 本地历史库、超过 7 天的流量历史、366 天流量档案。
- 当月（未出账）花费、预付费摊销、按天画年度花费。
- 多用户、多设备同步、账号导入导出、Web 端。
- 深色模式以外的主题定制（初版跟随系统）。

## Further Notes

- 默认值（可推翻）：包名 `com.cdndash.app`，`minSdk 26`、`targetSdk 35`，折线/柱图自绘 Canvas。
- 真机验收必须由使用者提供至少一个测试账号的只读 AccessKey；没有真实凭据只能验证到 Mock 层，交付说明中需写明「未对真实 OpenAPI 验证」。
- 该 RAM 用户的最小权限：`cdn:DescribeDomainTrafficData`、`cdn:DescribeCdnUserResourcePackage`、`bss:QueryAccountBill`。
- 与音乐业务的后台统计（ADR 0014）数字不同是设计使然（账号全量 vs 域名白名单），排查时先确认口径。
- 冷启动请求量：每账号首屏 2 次（今日 5 分钟 + 7 天 1 小时）+ 资源包最多 4 次（CDN/DCDN 双端点 × valid/exhaust），花费页按需 12 次；账号间并发需设上限，避免账号多时同时打满。
- 资源包明细页每次进入额外取一次 7 天（同一 `DescribeDomainTrafficData`），失败回落 `WEEK_TREND` 快照；看板与 5 分钟定时刷新不因估算增加请求（ADR 0018）。
- 预计可用天数只按 CDN 边缘出流量与 CDN/全站加速共享流量包估算：若账号还有 DCDN 流量共用 `dcdnpaybag`，实际可用天数可能更短；按范围不引入 DCDN 流量接口，文案用「约可用」而非承诺。
