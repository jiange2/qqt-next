# 本地音乐（本地文件夹扫描）

Status: ready-for-agent

## Problem Statement

用户在自己的手机里存了音乐文件，但这些文件在 App 里完全不可见：底部导航的「最近播放」只记录在线点播过的歌曲 ID，展示时还要回后端换取详情，断网即失效。用户想听自己设备上的歌，只能离开 App 去别的播放器；想整理这些文件的标题、专辑等信息，也没有任何入口。同时「最近播放」本身价值有限——它只是在线内容的一个切片。

## Solution

把底部导航第二个入口从「最近播放」改为「本地音乐」：用户授权一个或多个音乐文件夹后，App 扫描其中的音频文件并建立本地索引，以歌曲、专辑两种视图展示；本地歌曲可直接加入播放队列播放，断网可用。用户可以在 App 内修改本地歌曲的标题、艺术家、专辑、专辑艺术家、音轨号、年份（只做 App 内覆盖，不改文件），随时手动重新扫描以发现新增、移除或变化的文件。最近播放功能整体下线。

## User Stories

1. 作为本地音乐听众，我希望第一次进入本地音乐页时看到明确的说明和「选择音乐文件夹」按钮，以便知道这个页面需要我先授权目录。
2. 作为本地音乐听众，我希望选择文件夹时使用系统的目录选择器，以便精确控制 App 能看到哪些音乐。
3. 作为本地音乐听众，我希望选目录时不被要求授予全盘音频读取权限，以便不必为了听自己的歌交出整机文件的可见性。
4. 作为本地音乐听众，我希望授权后自动开始第一次扫描并看到进度，以便知道 App 正在做什么、大概还要多久。
5. 作为本地音乐听众，我希望扫描过程中可以取消，以便发现选错目录时立即止损。
6. 作为本地音乐听众，我希望取消扫描后保留上一次的完整结果，以便不会因为中途取消而得到一份残缺的歌单。
7. 作为本地音乐听众，我希望可以授权多个音乐文件夹，以便内部分区和 SD 卡里的音乐出现在同一个列表里。
8. 作为本地音乐听众，我希望添加与已有目录重叠的文件夹时被明确告知并拒绝，以便不会看到同一首歌重复出现。
9. 作为本地音乐听众，我希望可以移除某个已授权的文件夹，以便不再被不想听的目录干扰。
10. 作为本地音乐听众，我希望移除文件夹后其歌曲从列表消失，但我之前改过的元数据仍然保留，以便重新加回来时不用重做。
11. 作为本地音乐听众，我希望在「歌曲」视图看到所有扫描到的本地歌曲，以便按列表浏览和播放。
12. 作为本地音乐听众，我希望在「专辑」视图看到按专辑归并的卡片墙，以便像浏览专辑一样找歌。
13. 作为本地音乐听众，我希望点开某张本地专辑能看到它的歌曲列表，以便整张专辑连续播放。
14. 作为本地音乐听众，我希望歌曲按标题排序、专辑按专辑名排序、专辑内按音轨号排序，以便列表顺序符合直觉。
15. 作为本地音乐听众，我希望文件缺少标题标签时用文件名兜底，以便不会看到一列空白行。
16. 作为本地音乐听众，我希望文件缺少专辑标签时用所在文件夹名当专辑名，以便散装音乐也能成组展示。
17. 作为本地音乐听众，我希望两个文件夹中同名但不同专辑的歌曲不被错误合并，以便专辑视图不出现串组。
18. 作为本地音乐听众，我希望内容完全相同的重复文件只显示一条，以便列表不被复制品污染。
19. 作为本地音乐听众，我希望点击歌曲时以当前列表整体作为播放队列，以便连续播放不用一首首点。
20. 作为本地音乐听众，我希望点击本地专辑时以整张专辑作为播放队列，以便按专辑顺序聆听。
21. 作为本地音乐听众，我希望本地音乐的播放模式单独记忆，以便在本地内容里选随机不会影响在线专辑的播放模式。
22. 作为本地音乐听众，我希望重启 App 后能恢复上次正在播放的本地歌曲和进度，以便中断后接着听。
23. 作为本地音乐听众，我希望长按歌曲行打开编辑面板，以便在列表里直接修正标签。
24. 作为本地音乐听众，我希望在全屏播放器里也能打开同一个编辑面板，以便正在听的时候顺手改信息。
25. 作为本地音乐听众，我希望编辑标题、艺术家、专辑、专辑艺术家、音轨号和年份，以便把标签混乱的文件整理成想要的样子。
26. 作为本地音乐听众，我希望编辑结果在重新扫描、移动或重命名文件后仍然生效，以便整理文件夹不会白费功夫。
27. 作为本地音乐听众，我希望可以一键恢复某首歌的默认标签，以便改错后回到文件原本的值。
28. 作为本地音乐听众，我希望修改专辑信息后歌曲立即移动到对应专辑分组，以便所见即所得。
29. 作为本地音乐听众，我希望专辑封面优先使用文件夹里的封面图片、没有时使用音频内嵌图，以便专辑墙有封面可看。
30. 作为本地音乐听众，我希望点击顶部菜单里的「重新扫描」手动刷新，以便新增、删除或替换文件后列表能自愈。
31. 作为本地音乐听众，我希望重新扫描是增量的并提示新增与移除的数量，以便知道这次扫描到底改变了什么。
32. 作为本地音乐听众，我希望重新扫描时旧列表仍然可用，以便扫描期间不必盯着空白页。
33. 作为本地音乐听众，我希望正在播放时重新扫描不打断播放，以便整理音乐库不影响听歌。
34. 作为本地音乐听众，我希望文件被删除或无法读取时该行灰显并提示，而不是整页清空，以便看懂发生了什么。
35. 作为本地音乐听众，我希望文件夹授权被系统回收时看到明确的重选引导，以便知道不是歌丢了而是权限没了。
36. 作为本地音乐听众，我希望本地音乐完全离线可用，以便飞行模式下照样浏览和播放。
37. 作为本地音乐听众，我希望本地歌曲不出现收藏、加入歌单、评分、下载和歌词入口，以便不点到注定失败的功能。
38. 作为本地音乐听众，我希望本地音乐页不发起任何网络请求，以便在服务器不可达时也不出现离线横幅或错误提示。
39. 作为本地音乐听众，我希望最近播放从底部导航消失后，收藏页仍然正常工作，以便这次改造不影响已有功能。

## Implementation Decisions

### 导航与页面

- 底部导航第二个入口由「最近播放」改为「本地音乐」，沿用该位置与现有路由入口。
- 删除最近播放页面、其 ViewModel、播放时的最近播放写入点与本地最近播放键；升级后首次启动清理该键的残留。
- 后端 `get_recent_songs` 接口与客户端方法保留：收藏页仍在用它按 ID 批量换取歌曲详情。
- 本地音乐页由「歌曲 / 专辑」两视图组成，用分段控件切换，进入页面默认歌曲视图，不记忆上次视图。
- 顶部应用栏右侧菜单提供「重新扫描」「添加音乐文件夹」「管理音乐文件夹」；管理列表可移除某个根目录。
- 本地专辑页为独立页面，展示该专辑的歌曲；专辑键需要 URL 安全编码以便作为路由参数。
- 未授权任何文件夹时展示引导空态；已授权但结果为空时展示另一套空态（提示目录中可能没有支持的音频格式）并提供重新扫描入口。

### 扫描与索引

- 扫描通过 SAF 目录树进行：用户选择目录后用持久化授权保存，App 自行递归遍历，不使用 MediaStore，不申请任何存储权限。
- 音频格式白名单：`mp3 / m4a / aac / flac / ogg / opus / wav`；跳过以 `.` 开头的隐藏目录与文件，目录级尊重 `.nomedia`；不设最短时长过滤。
- 遍历深度不限；同一份音乐被多个重叠根目录覆盖时按歌曲身份去重。
- 歌曲身份为内容指纹：文件大小 + 首 32KB 与尾 32KB 的 SHA-256（不足 64KB 取全文）。路径与 SAF documentId 只用于定位与快速跳过。
- 重扫先按「路径 + 大小 + 修改时间」跳过未变文件；新增或变更的文件才计算指纹、重新读取标签。
- 标签读取使用 `MediaMetadataRetriever`，字段为标题、艺术家、专辑、专辑艺术家、音轨号、年份、时长；缺失时标题回退为去掉扩展名的文件名。
- 重新扫描为增量合并：新增入列、消失移除、变更重读；覆盖层按身份保留。文件消失只从索引移除，不删除覆盖层。
- 扫描是原子提交：在新索引构建完成前不替换现有索引；取消或失败时丢弃本次结果并保留上一次完整状态。
- 同一时刻只允许一个扫描任务，新扫描会取消旧扫描。
- 扫描完成后轻提示「新增 x 首、移除 y 首」。
- 移除某个根目录时，直接从内存索引剔除归属于该树的歌曲，不触发全量重扫。

### 持久化

- 使用两个 App 私有 JSON 文件，均原子写入（临时文件 + rename），全部读写发生在 IO 线程：
  - **扫描索引**：根目录列表 + 每首歌的身份、documentUri、所属树、相对路径、显示文件名、大小、修改时间、时长、标签快照与可用状态。
  - **覆盖层**：身份 → 用户改过的字段，只存非空值。
- 两个文件都带版本号，便于以后迁移；不引入 Room 或其他数据库。
- 展示值 = 覆盖值优先，缺失则取标签快照；所有列表、播放器、专辑分组的展示都必须走这一个合并结果。
- 清空某个字段等于从覆盖层删除该字段，回到文件标签值。
- 启动时在 IO 线程加载并合并两份文件，不做任何网络请求。

### 身份与播放

- 本地歌曲对播放兼容层暴露的 ID 为 `local:<指纹十六进制>`，与后端数字 ID 的命名空间天然隔离。
- 播放队列元素沿用现有歌曲模型：URL 为文件 content URI，标题/艺术家/时长取合并后的展示值，封面为本地封面缓存，歌词字段为空。
- 播放队列新增来源键 `local`，本地音乐页与本地专辑页共用同一份来源记忆（ADR 0015 的键空间扩展，已写入术语「来源记忆」）。
- 队列快照继续保存整队列副本，因此本地歌曲的播放进度可以被恢复；持久化授权保证重启后 URI 仍可读。
- 播放器遇到 `local:` 歌曲时不请求后端详情、不加载歌词、不显示收藏/加入歌单/评分/下载入口。
- 本地歌曲播放失败（文件被删或不可读）时提示「文件不可用」、把该行标记为不可用并灰显，不自动重扫；下次重新扫描时移除。

### 专辑与封面

- 专辑分组键为「专辑名 + 专辑艺术家」的合并展示值；专辑名为空时回退到「所在文件夹名 + 文件夹路径」作为分组键，不同文件夹的同名专辑互不合并。
- 专辑内排序：音轨号升序，音轨号为空按标题；专辑之间按专辑名升序；歌曲视图按标题升序。全部使用 `java.text.Collator(Locale.CHINA)`。
- 封面来源优先级：歌曲所在文件夹的封面文件（`cover / folder / front / album`，`jpg / jpeg / png / webp`）→ 音频内嵌图 → 占位图。
- 封面按专辑键缓存到 App 私有目录，懒加载，缓存容量设上限并按最近使用淘汰；文件夹封面变化需重扫后感知。

### 元数据编辑

- 编辑面板为底部弹层，字段为标题、艺术家、专辑、专辑艺术家、音轨号、年份，外加「恢复默认」。
- 入口两个：长按歌曲行；全屏播放器的「更多菜单」中的「编辑信息」（仅当前歌曲为本地歌曲时出现）。
- 音轨号只接受正整数，年份只接受四位数字，首尾空白统一裁剪；保存后立即刷新歌曲列表、专辑分组与专辑封面。
- 编辑只写覆盖层，绝不回写音频文件标签（ADR 0020）。
- 编辑导致专辑内歌曲清空时，该专辑从专辑视图消失。

### 权限与失效

- 进入本地音乐页时检查每个根目录的持久化授权：全部失效 → 引导空态 + 重新选择；部分失效 → 提示并提供管理入口，来自失效目录的歌曲按不可用灰显。
- 不添加 Android 13+ 的音频读取权限，也不申请任何运行时存储权限。

### 文档

- `android/CONTEXT.md` 已补充「本地音乐」「本地歌曲」「本地专辑」词条，并把「本地歌单」正名为「我的歌单」。
- ADR：0019（SAF 文件夹扫描）、0020（元数据覆盖层）、0021（内容指纹身份）。
- 需要同步更新 Android 的存储与 UI 说明文档，删除最近播放相关描述。

## Testing Decisions

- 本项目当前只有两个示例测试，没有可复用的测试接缝。经确认，本功能**不新增自动化测试**，验收走手工清单。
- 手工验收覆盖以下外部行为：
  - 首次进入无权限、无内容；选择目录后自动扫描并出现歌曲。
  - 扫描中取消，索引保持上一次完整状态；重新扫描提示新增/移除数量。
  - 同一首歌被移动或改名后重扫，覆盖层仍生效；内容相同的副本只出现一条。
  - 无标签文件回退文件名；无专辑名回退文件夹；编辑专辑后歌曲换组。
  - 播放本地歌曲、整张本地专辑；重启后恢复队列与进度；播放模式在本地来源单独记忆。
  - 飞行模式下浏览、播放、编辑、重扫全部可用，页面不出现网络错误或离线横幅。
  - 删除正在播放的文件后再点播 → 灰显与提示；撤销文件夹授权 → 重选引导。
  - 本地歌曲在全屏播放器不出现收藏/歌单/评分/下载/歌词入口。
- 若将来补自动化测试，最高接缝是把「索引合并、指纹、增量 diff、覆盖合并、专辑分组与排序」收敛为纯 Kotlin 核心、文件与标签读取以接口注入，在 JVM 单测覆盖；SAF 遍历与标签读取只做一次仪器冒烟。

## Out of Scope

- 修改专辑封面。
- 把标签写回音频文件（ID3/tag 回写）。
- 本地歌曲进入收藏、我的歌单、评分、下载。
- 把「下载列表」的已下载歌曲并入本地音乐。
- 使用 MediaStore 索引或任何全机音频读取权限。
- 后台自动重扫、文件变更监听。
- 批量编辑、按文件夹浏览视图、本地音乐内的搜索。
- 本地歌曲的歌词。
- 排序菜单、多选、拖拽排序。
- 专辑级批量编辑（改一次专辑名影响整张专辑）。
- M3U 等歌单文件导入导出。

## Further Notes

- 最近播放下线后，收藏页仍依赖 `get_recent_songs` 按 ID 换详情，接口与服务端不要改动；本次改造对后端零改动。
- `minSdk 21`：SAF 目录授权自 5.0 可用；`MediaMetadataRetriever` 支持 content URI；`Collator` 为 JDK 自带，无需引入拼音库。
- `MediaMetadataRetriever` 是扫描的主要成本：逐个文件串行读取、放 IO 线程，避免大量并发打开文件；扫描期间不得阻塞主线程。
- 本地封面缓存会随专辑数量增长，必须有上限与淘汰策略，避免成为第二个无界缓存。
- 队列快照里会出现 content URI；只要持久化授权还在，冷启动恢复即可正常播放。
- 本地音乐与「下载列表」是两个互不包含的集合：前者是用户设备上的文件，后者是 App 自己下载到私有目录的内容。
- 本次改造不动「响应快照」「服务器不可达」等网络降级机制；本地音乐页根本不发起网络请求。
