# 本地音乐批量管理（编辑模式多选改专辑/专辑艺术家）

Status: ready-for-agent

> 延续 ADR 0020（元数据只写 App 内覆盖层、不回写文件标签）与 ADR 0022（MediaStore 来源、行 ID 身份），不推翻任何 ADR。批量编辑收回 v1 / rescan spec 的 Out of Scope 边界（当时明确不做），是新增能力而非架构变更。基线含已归档的视图切换特性（main 822234d：默认专辑视图、切换进顶栏 ⋮ 菜单）。

## Problem Statement

本地音乐目前只能长按单首编辑元数据。整理多首歌的专辑 / 专辑艺术家（把散落的歌归并进一张专辑、修正整批文件的错误专辑名）要逐首长按、逐次保存，成本随歌曲数线性增长。用户需要批量管理：右上角进编辑模式，多选后一次改专辑、专辑艺术家。

## Solution

本地音乐页歌曲视图新增编辑模式：顶栏 ⋮ 菜单加「批量管理」项（仅歌曲视图显示、无音频权限禁用）；进入后歌行前出现勾选框，点行 / 长按 = 勾选（不跳播、不弹单首面板、左滑删除收起），顶栏变「取消 / 全选 / 已选 n 首」，底栏出现「编辑信息」按钮；点开批量面板（ModalBottomSheet，仅专辑、专辑艺术家两个自由文本字段，初始为空）；填了的字段才改、留空保持原样；保存一次原子提交写覆盖层（整表一次落盘），Toast「已修改 n 首」并自动退出编辑模式。改动只影响本 App 展示（ADR 0020），不动音频文件；专辑归并键不变（专辑名 + 专辑艺术家），批量改完歌曲按新值换组。

## User Stories

1. 作为本地音乐听众，我在歌曲视图点 ⋮ → 批量管理进入编辑模式，以便开始多选整理。
2. 作为本地音乐听众，我点歌行或长按歌行 = 勾选 / 取消勾选，不跳播、不弹单首编辑面板，以便连续勾选。
3. 作为本地音乐听众，我看到顶栏「取消」「全选 / 取消全选」「已选 n 首」，全选勾上当前列表全部可用行（灰显不可用行跳过），以便快速整库操作。
4. 作为本地音乐听众，我在已选 ≥1 首时点底栏「编辑信息」打开批量面板，以便一次改多首。
5. 作为本地音乐听众，我看到面板只有专辑、专辑艺术家两个输入框且初始为空，留空的字段不改（与单首面板「留空 = 恢复文件原值」相反），以便只改想改的字段。
6. 作为本地音乐听众，我在两个字段都留空时看到保存禁用，以便不会提交无意义操作。
7. 作为本地音乐听众，我保存后看到 Toast「已修改 n 首」并自动退出编辑模式，改动即时生效，以便所见即所得。
8. 作为本地音乐听众，我只填专辑名时歌曲按各自原专辑艺术家落组（可能拆成多张同名不同艺术家的专辑），两个字段都填才并进同一张——与单首编辑一致，以便归并行为可预期。
9. 作为本地音乐听众，我点取消或按系统返回退出编辑模式、清空勾选、丢弃未保存输入，以便随时反悔。
10. 作为本地音乐听众，我切底部 Tab 或进其他页面即退出编辑模式，回来是正常态，以便选择态不跨页残留。
11. 作为本地音乐听众，我在无音频权限时看到「批量管理」菜单项禁用；编辑中途权限被收回时整库灰显并退出编辑模式，以便权限口径一致。
12. 作为本地音乐听众，我批量改完重扫后改动仍生效（覆盖层按行 ID 合并，现有机制），以便整理成果不丢。
13. 作为本地音乐听众，我在编辑模式下看不到左滑删除，以便勾选交互不与行内手势打架。

## Implementation Decisions

### 入口与菜单

- ⋮ 菜单顺序：视图切换 / 批量管理 / 重新扫描 / 排除的文件夹。「批量管理」仅歌曲视图（`!showAlbums`）显示；专辑视图不显示（编辑模式只做歌曲列表，专辑卡片墙与本地专辑页不做）。
- 权限门槛沿用「重新扫描」的 `rescanEnabled` 范式：`permissionGranted = false` 时禁用。空库不额外禁用（进入后无行可选，全选为 no-op）。
- 点击进入编辑模式并收起菜单、收起左滑展开态。
- 基线：视图切换特性已归档合入 main（822234d），菜单第一项已是视图切换；本特性直接在其后插入，无跨 spec 票据依赖。

### 编辑模式状态与选择态

- 编辑模式开关与勾选集合（`Set<LocalSong.id>`，即 `local:<卷名:行ID>` 身份键）提升到导航层 `AppNavigation`，`remember` 以 `local_music` 返回栈条目为键（与视图状态同构）：离开本页键置空、状态重建，「离开即退出、勾选不保留」由结构保证。不放 `LocalMusicViewModel`——它是导航层单例、与专辑页 / 播放器共用，放进去会跨页泄漏。
- 点行与长按都切换勾选；编辑模式下歌行左滑删除收起（`swipe = null`）、长按不再弹单首面板。
- 不可用行（`available = false`）不可勾选、全选跳过。
- 全选 = 当前歌曲列表全部可勾选行（排除文件夹后的可见列表）；已全选时再点 = 清空勾选。
- 系统返回 = 退出编辑模式（`BackHandler`），不退出页面。

### 顶栏与底栏

- 编辑模式下本地音乐页顶栏替换为「取消 / 全选·取消全选 / 已选 n 首」（`MusicTopBar` 的本地音乐分支按编辑态切换）；⋮ 菜单在编辑模式下隐藏。
- 底栏批量操作栏只有一个「编辑信息」按钮，已选 0 首禁用；只在编辑模式渲染；与 MiniPlayer / 底部导航的避让沿用现有 Scaffold 结构。

### 批量面板

- 复用 ModalBottomSheet 范式（与 `LocalMetadataEditSheet` 同款），仅专辑、专辑艺术家两个自由文本字段，初始为空、不预填；无「恢复默认」按钮。
- 保存禁用条件 = 两字段 trim 后皆空。
- 字段标签用规范词「专辑」「专辑艺术家」（CONTEXT.md，弃用「专辑作者」）。

### 批量提交语义（数据层）

- 新纯函数（`LocalMetadataEdit.kt`）：按「填了的字段才改」生成每首歌的新覆盖——输入 trim 后留空 → 保留原覆盖该字段；非空且与文件标签值相同 → 该字段覆盖置 null（不制造冻结标签的假覆盖，沿用 `overrideIfCustom` 口径）；其余 → 存裁剪值。标题 / 艺术家 / 音轨号 / 年份四个字段原样保留。
- 生成的覆盖 `isEmpty` → 从覆盖表删该键（沿用单首「空壳不落盘」口径）。
- ViewModel 新批量保存入口：一次 `editLock.withLock` 内整表更新覆盖 Map → 替换 `_songs` 选中条目（`available` 取快照本值，沿用单首范式）→ `sortedByDisplayTitle`（改专辑不改标题，行序实际不变）→ `LocalMusicStore.saveOverlay` 一次原子落盘。不走 N 次 `applyOverride`（避免 N 次落盘与 N 次重排）。
- 快照不动、不重查、不碰文件；专辑分组 / 计数从 `_songs` 派生自动重算，换组后新旧专辑按成员行 `albumArtUri` 重新取图（现有机制，封面不可自定义）。
- 播放器 / MiniPlayer / 队列只显示标题 + 艺术家，批量改专辑 / 专辑艺术家不影响播放器文案，无需播放器同步。

### 反馈与退出

- 成功 Toast「已修改 n 首」（n = 勾选提交数，不按实际值变化数），经现有 `notice` StateFlow → 导航层 collector 弹出（两页共用口径）。
- 保存成功即退出编辑模式、清空勾选、关闭面板。
- 覆盖层落盘失败只记日志（`LocalMusicStore.writeAtomically` 现有口径），内存态已更新。
- 编辑中途 `permissionGranted` 变 false：退出编辑模式，沿用整库灰显。

### 文档

- CONTEXT.md 已新增「专辑艺术家」「编辑模式」「批量管理」三条词条（grilling 期间落地），「专辑作者」列入弃用词。
- `android/doc/ui.md`：LocalMusicScreen 节补编辑模式（入口、选择态、顶栏 / 底栏、批量面板、退出路径）；LocalMetadataEditSheet 节补批量变体（双字段、留空 = 不改）。
- `android/doc/storage.md`：覆盖层节补批量提交（一次整表原子写、与单首共用 editLock）。
- 不新增 ADR：沿袭 ADR 0020 / 0022，批量语义记入词条与本 spec；三条门槛（难以反转 / 无上下文会让人惊讶 / 真实取舍）均不成立——覆盖层批量写是可逆的数据层扩展，「留空 = 不改」已在词条写明。

## Testing Decisions

- 纯函数 JVM 测试：批量覆盖生成（留空保留原覆盖、填值写入、与标签同值清覆盖、其余四字段保留、全空覆盖删键、trim）与批量提交后的列表 / 覆盖表形态。本仓规约：AI 不编译、不跑 gradlew，测试已写待人工执行。
- 设备级验收清单（各票未勾选项）：菜单入口与权限禁用、勾选 / 全选 / 计数、面板留空语义、保存换组与封面、Toast 与退出、返回 / 切页 / 权限收回、重扫后保留、左滑收起、飞行模式可用（纯本地）。

## Out of Scope

- 批量删除、删除整张专辑 / 文件夹（delete spec 边界不变）。
- 批量改标题 / 艺术家 / 音轨号 / 年份等其他字段。
- 专辑卡片墙整张专辑勾选、本地专辑详情页编辑模式（其顶栏带返回键、现有 TopBar 不渲染 actions；且页内改专辑会让当前专辑键消失，需导航联动，本次不做）。
- 写回文件标签（ADR 0020 不变，其他播放器看到的仍是文件原标签）。
- 批量「恢复默认」（打回文件原值仍走单首面板）。
- 自定义专辑封面（封面仍取成员行系统预抽取图）。
- 选择态跨页面 / 跨进程保留、编辑模式记忆。
- 本地音乐内搜索、排序菜单（沿用既有 Out of Scope）。

## Further Notes

- 只填专辑名会按各自专辑艺术家拆组（grilling Q7 已确认保持）：归并键 = 专辑名 + 专辑艺术家，批量不另造归并语义。
- 覆盖层按行 ID 记键：文件删除后重加 = 新行 = 编辑丢失（ADR 0022 已知取舍，批量不改变）。
- 专辑艺术家列 API 30+ 才有值，低版本标签为空——批量填值照样可写覆盖（覆盖层不依赖该列存在）。
- 批量保存沿用 `editLock` 与单首编辑串行；与在途刷新的竞态沿用既有已知取舍（最后写入胜出），不额外缓解。
- 默认视图已是专辑视图：用户需先 ⋮ → 切换到歌曲视图再进批量管理（grilling Q4 已确认接受此代价）。
- grilling 期间子代理曾报 view-switch 未实现（基于旧提交 7e87850）；落 spec 前核实其已归档合入 main（822234d），Q6 的「view-switch 在前」已天然满足，无跨 spec 依赖。
