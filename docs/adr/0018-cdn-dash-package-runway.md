# CDN 看板用区域近 7 天日均估算资源包可用天数

初版 spec 把「资源包预计耗尽日」列入 Out of Scope，理由是余量、到期日与 7 天流量各自已经够用，再推一个日期容易变成承诺。实际使用中最常问的却是「这个包还能撑几天、要不要补量」；而 `DescribeDomainTrafficData` 的每个数据点本来就返回 `DomesticValue`/`OverseasValue`，区域消耗速度是现成的，不增加任何请求。这次把该推算纳入范围，但必须把口径、边界与数据来源写死，否则「剩 500G 还能用几天」会因算法不同给出互相矛盾的数字。

## 决策

1. **按（区域，到期日）组估算，不跨区域**：可用天数 = 该组 `usableRemainingBytes ÷ 该区域最近 7 个已结算日的日均边缘出流量`。不同区域的包不可互相抵扣，分子与分母必须同区域；未生效的组可用余量按 0，直接不估算（GLOSSARY「区域」「区域日均」「预计可用天数」）。
2. **日均取同一 7 天响应的区域拆分**：分母固定除以 7，缺日已在聚合时补 0；`DomesticValue`/`OverseasValue` 与 7 天总量同一次请求解析，看板与 5 分钟定时刷新零新增请求。明细页没有看板的数据，进页自行取一次 7 天（每次 +1 请求），失败回落 `WEEK_TREND` 快照。
3. **先比到期、再取整**：用**未取整**的原始天数与剩余到期天数比较，原始天数 ≥ 剩余到期天数即「到期前用不完」——若先四舍五入，5.7 天会被抬成 6 天，与「还剩 6 天到期」误判成用不完。比较通过后再展示：不足 0.5 天 → 「不足 1 天」，超过 999 天 → 「>999 天」，其余四舍五入；预计用完日按北京自然日显示 `MM-dd`。
4. **区分「没有数据」「零流量」与「离线」**：区域未知、旧快照没有区域字段（总量有值但区域全 0）时不显示任何估算，避免把「不知道」说成「不消耗」；本区域 7 天为 0 时显示「近 7 天无流量，暂不估算」。7 天来自离线快照时仍给天数（估算值不受影响），但不再推算具体日期，避免用旧数据给出看似精确的「哪天用完」。
5. **快照向后兼容**：`DayTrafficPoint` 新增区域字段并带默认 0；旧 `WEEK_TREND` 载荷照常解码，区域为 0 的旧数据按「区域数据缺失」静默，下一次成功取数后自动变得可估算。

## Considered Options

- **账号级日均（总量 ÷ 7）**：被否——中国内地与海外的包会被同一个速度误配，海外包可能显示「到期前用不完」而内地包被高估；跨区域误配正是 GLOSSARY 禁止的求和。
- **顺序消耗模型（先耗尽先到期、到期未用完即作废、再滚入下一组）**：被否——需要按到期顺序模拟多组消耗，规则复杂、对「同时有多个区域/多个到期日」给出的是模拟值而非事实，且无法解释单组数字。
- **新增专用接口（DCDN 流量、资源包消耗明细）**：被否——现有响应已含区域拆分；新增接口要额外权限、额外请求，且按范围不做 DCDN 流量统计。
- **用今日累计估算**：被否——今天未结算、只有半日数据，波动大；「已结算日」才是稳定口径。
- **日粒度接口取 7 天**：被否——4–24 小时延迟会让昨日半截；继续用小时粒度取回后按北京日汇总（ADR 0016）。

## Consequences

- **估算会随 7 天窗口滚动而变化**：文案统一用「约可用」「预计」，不写成承诺；包快到期时以「到期前用不完」代替大数字。
- **共享包的消耗可能被低估**：`dcdnpaybag` 也抵扣 DCDN 流量，但本应用按范围不取 DCDN 流量；若账号同时跑 DCDN，实际可用天数可能更短，说明书与 spec 需保留该提示。
- **旧快照的过渡期**：升级后首次成功刷新前，历史 `WEEK_TREND` 快照没有区域字段，估算静默；这是有意的，不把 0 当零消耗。
- **区域码归一**：资源包接口的 `Region` 实际返回区域码（文档示例 `CN`，海外为 `OVERSEAS`），不是 GLOSSARY 的中文区域名。分组入口统一经 `canonicalRegion` 归一为「中国内地/海外」；漏掉这一步会让所有组被判为「区域未知」而静默不估算（2026-11-27 真机实测发现的缺陷）。无法识别的值原样展示、不参与估算。
- **请求预算**：看板不变；资源包明细页每次进入多 1 次 `DescribeDomainTrafficData`，失败不影响包列表与错误态。
