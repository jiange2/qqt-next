# Node.js 重写后端，旧协议门面保持 Android 零改动

PHP 后端（`backend/`）由采购模板演化而来，缺陷已实锤（热门歌曲去重失败、文档与代码严重不符），维护成本高。决定用 Node.js 22 + TypeScript + Fastify + Prisma 重写整套服务（API + 管理面板，面板为 Vue 3 + Element Plus），代码置于 `backend-next/`（`server/` + `admin-web/`），短并存后一次性割接替换，PHP 下线。

**决定**：

1. **旧协议门面原样复刻**（对齐 ADR 0001 的约束）：`/legacy` 路由完整实现 `api.php` 的全部 32 个 method（以代码为准，非文档记载的 17 个），sign/salt 签名、`ONLINE_MP3` 根节点、数值字符串化、响应文案逐字保留。做**语义兼容**而非逐字节兼容——逐字节会把旧实现的 bug 固化；已实锤的缺陷不复刻。
2. **新 Schema + 内容优先迁移**：逗号分隔关联全部规范化为关联表，时间戳改 DATETIME，密码一律 bcrypt。只迁内容实体、全局设置与媒体文件（保留原实体 ID）；**用户及其行为数据（收藏/评论/举报/建议）整体放弃**，从零积累——用户活跃度低，任何密码迁移方案的成本都高于收益。
3. **同进程双路由**：`/legacy`（仅对 App）+ `/admin`（REST/JSON + JWT，仅对新管理面板）共享服务层，为将来第三套现代 App API 预留扩展点。
4. **热门歌曲改为管理员固定榜**（`trending_songs` 关联表）：播放量不再驱动首页榜单，播放统计表不需要存在；`total_views` 计数器保留仅作展示。
5. **邮件功能整体移除**：注册即生效、无验证邮件、无找回密码（`forgot_pass` method 保留但只返回提示）；存储保留本地文件（URL 路径形态不变），但 URL 生成集中管理，为将来迁移 OSS 只改一层。

**被否决的替代**：双写/增量同步（工程成本与出错面远超短期冻结写入窗口）；管理面板沿用旧协议（自缚手脚）；对象存储立即上马（违反 Android 零改动原则）。

**割接步骤**：冻结旧后台写入 → 一次性迁移脚本（数据 + 媒体文件复制）→ 黄金样本契约测试 + 真机主流程验证 → 切换 → PHP 容器下线，`backend/` 删除。
