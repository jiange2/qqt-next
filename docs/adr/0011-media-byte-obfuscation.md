# 媒体字节混淆：音频与图片对象逐字节 +31 存储，客户端还原

OSS 直链 + CDN 明文 HTTP 分发（ADR 0005、0006）使媒体可被直链抓取。决定：`uploads/`、`images/`（含 `images/thumbs/`）对象以逐字节 +31（模 256）的确定性混淆存储——无密钥，目标仅是抬高直链抓取门槛，不追求密码学强度；App 播放数据源与图片加载链路、管理面板图片展示各自 -31 还原。已混淆对象以自定义元数据 `encrypted=1` 标记，管理面板提供批量补混淆（按元数据跳过，幂等可反复执行）与 CDN 刷新 URL 导出；新上传（含外链转入 OSS）在服务端写入时即混淆并标记。歌词（ADR 0010）与书籍正文（存 DB）不参与。

## Considered Options

- **真加密（AES，如歌词密文）**：被拒——App 需内置密钥，泄露即整体失效，对抬高直链抓取门槛无增益。
- **服务端解混淆代理**：被拒——播放与管理面板图片全部改经服务器回源，服务器带宽小、承担不起媒体流量；CDN 直出 + 端侧还原保持现有分发架构不变。
- **端侧魔数嗅探兼容新旧混杂**：音频被拒——mp3 无 ID3 帧起头时误判约 1/2048，ExoPlayer seek 后 Range 非 0 开流使判定进一步复杂。图片侧割接后补充采纳：图片魔数（JPEG/PNG/GIF/WebP/BMP/AVIF）空间稀疏，混淆态误判为明文的概率可忽略，App 图片链路与管理面板按「魔数判明文直认、否则 -31」双态兼容，CDN 残留明文旧缓存可自愈；音频仍靠有序割接（全量补混淆 → CDN 刷新 → 再发解混淆版 App）保证，设备端割接窗口写下的毒化缓存条目另靠播放期错误重试自愈兜底（见 Consequences）。

## Consequences

- 客户端与 OSS 内容强耦合：全量混淆后旧版（不解混淆）App 即失效，须按上述割接顺序执行；此后媒体对象必须一律带混淆写入（上传、OSS 直传、外链转入统一收口），漏写即用户侧花图/坏音。
- 本地明文：设备端被动缓存与已下载文件保存还原后明文——混淆目标不含已 root 的本机。
- 同 key 重写会把对象元数据重置为目录默认缓存头（个别手动自定义的缓存头会丢失，音频本就不设、图片本就 365 天，可接受）；重写后 CDN/浏览器可能仍回旧明文，靠割接流程中的 CDN 刷新清除。
- 管理面板图片改走浏览器端还原（fetch CDN → 魔数判定 → 还原 → objectURL 喂 el-image），要求 CDN 域名配置 CORS 响应头；管理面板无音频播放，音频还原仅存在于 App。
- ADR 0005 的「明文可接受」立场修订为「传输保持明文 HTTP，内容字节混淆」；防盗链（ADR 0006）与访问统计口径不受影响。
- 端侧存量缓存版本化割接：被动缓存键统一带版本后缀（AudioCache.cacheKey，CacheDataSource 两处 CacheKeyFactory 同口径），Coil 盘存目录按 `image_cache_v3` 起；旧版本键/目录启动时一次性清除。前提——已下载文件与旧版缓存本就是明文、与新链路天然兼容，版本化的目的是作废割接窗口期写下的坏字节条目（如混淆初版无嗅探时连明文 CDN 测试）；此后凡缓存语义变更（位移量、媒体 host 等）版本号 +1 即整体作废。
- 音频错误重试自愈（割接后补充采纳）：毒化被动缓存条目不随 CDN 刷新消失，播放报解析/解码错（仅 3xxx/4xxx，IO 类是网络问题不参与）即清除对应被动缓存条目重新装载痊愈；同曲再败升级 `#raw` 通道（fragment 不随请求发往服务器、参与缓存键形成独立命名空间）旁路 -31 直读，兜底 CDN 残留明文；`#raw` 再败即停防循环。残余缺口：极小概率同步字凑巧不报错（噪声播放连「失败」都不算）、自愈窗口内「下载」仍会落盘乱码文件（mp3 无魔数可校验）。
