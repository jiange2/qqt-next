# 下载二维码：后台生成、服务端令牌入口与到期时刻，过期或重掷即失效

管理面板「应用设置 · 下载二维码」为分发方生成一张带期限的下载二维码。二维码内容是令牌链接 `<服务器 IP>/download/q/<随机令牌>`（缺省 `http://101.132.159.145`，可用 `DOWNLOAD_PUBLIC_BASE` 覆写）——走 IP 的 80 明文入口，不碰域名，也不经域名 80→HTTPS 的默认跳转，故宿主 Nginx 要给该 IP 单独放行 `/download/`（否则落进 80 的 default_server 被 301，且 `return 301` 不带 `$request_uri` 会连路径一起丢掉）。令牌与绝对到期时刻成对存于 settings 单行（本 ADR 引入 `download_qr_token` / `download_qr_expires_at` 两列），每次请求时校验——令牌不匹配或已过到期时刻一律真 404（与「路由不存在」的默认响应同形，不泄漏任何信息）。生成即重掷：点一次生成按钮就换一个新令牌并设一个新到期时刻，旧二维码当场失效，不必等它自然到期。全程没有任何定时任务或清理作业：到期是校验时算出来的，不是一个被写下的状态。

扫码后的分流由服务端按令牌动态渲染的「扫码落点页」承担。非微信浏览器进页即 `location.replace` 到 `/download/q/<令牌>/apk`，该地址再校验一次令牌后 302 到「跳转地址」（appRedirectUrl，与 App 内更新、静态下载页同源），安装包字节一律不经本服务中转。微信内置浏览器（UA 含 `MicroMessenger`）不跳转，展示引导浮层「点击右上角 ··· 选择『在浏览器打开』」，浮层内附「复制下载链接」——该页是明文 HTTP，`navigator.clipboard` 不可用，复制走 `execCommand` 兼容路径。落点页的版本号在服务端渲染时从 settings 内联，不再请求 `app-meta`。

期限只锁「二维码入口」这一条路：`/download/` 静态页、`/download/apk` 与安装包直链保持原有公开行为（沿 ADR 0012 的入口边界），知道直链的人不受二维码期限约束。这是有意的——App 内更新链路直接打开同一公开直链，ADR 0006 已否决 CDN 鉴权与签名 URL，期限只能落在自己能控制的入口上。后台的二维码图片由 admin-web 用 `qrcode` 前端渲染，链接不落盘、不入 OSS。

## Considered Options

- **OSS 侧实现（对象生命周期 / 防盗链 / 签名直链）**：被拒——OSS 没有「链接级时间语义」这种东西：生命周期作用于对象本身（删了谁都下不了，且动的是 App 更新链路依赖的唯一文件），Referer 防盗链与签名 URL 在 ADR 0006 已被否决。
- **令牌存独立表 + 定时任务清理**：被拒——只有一个分发入口，settings 单行即够；到期是请求时判定，不需要任何调度器，「过期」也就不会被某个作业延迟或漏掉。
- **多码并存（各自到期、可分别撤销）**：被拒——当前只有一个分发入口，多码并存会引入「哪张才是官网在用的」的额外心智，并牵出命名、扫码统计等配套；将来真要多码再另立方案。
- **令牌与到期并入设置表单（putSettings 白名单）**：被拒——设置表单是整体覆盖式保存，任何一个只加载了旧表单的页面保存一次就会把令牌/到期覆盖掉；且「生成二维码」是带确认的破坏性动作，与「保存设置」语义不同，故独立端点（`GET/PUT /admin/download-qr`）各管各的。
- **二维码内容直接放安装包直链**：被拒——期限无从附着，且换包即换码；令牌入口把「入口」与「文件地址」解耦，换安装包地址不影响已发出的二维码。
- **二维码链接沿用域名入口（`qqt.yunshangzhiai7.top` 的 80 通路）**：被拒——二维码发出去就收不回来，入口要选最不受外部条件牵动的那个：域名会受解析、证书、80→HTTPS 跳转策略变动牵连，IP 直出不经 DNS 也不经任何跳转（沿用 ADR 0009 对域名故障的对冲思路），代价是必须靠 Nginx 单独放行 `/download/`。
- **扫码落点直接 302 到安装包（不设页面）**：被拒——微信内 302 到 APK 一样被拦，用户只得到空白页；页面才能承载引导与「复制链接」，是微信场景唯一能给出下一步的地方。
- **服务端生成二维码图片并存入 OSS**：被拒——多一次上传与后续清理，图片随时可从链接重生成，没有服务端持有的理由。
- **扫码统计（计数/明细）**：被拒——本轮不需要；服务端只做校验不做记录，落点页也不埋点。

## Consequences

- 期限是「入口开关」不是「文件保护」：安装包直链保持公开（App 更新链路与静态下载页共用），绕过二维码即可直接下载——这是设计的边界，不是漏洞。
- 重掷即时失效，且没有「只延长到期、不换令牌」的操作：续期＝重新生成＝旧码作废，已发出的旧二维码要重新分发。
- 到期不清库：令牌与到期时刻保留在 settings 行内，后台据此显示「有效 / 已过期 / 尚未生成」与剩余时间（30 秒刷新），是否生成新码由管理员决定。
- 二维码即凭证：不绑定任何身份，截图、转发、打印件等效，期限内谁扫都能下载；泄露只能靠重掷止损。
- 二维码链接的入口由服务端配置 `DOWNLOAD_PUBLIC_BASE` 决定（缺省服务器 IP `http://101.132.159.145`；尾部斜杠会被去掉，避免拼出 `//download` 让 Nginx 前缀匹配落空）：改配置只影响之后生成的二维码，已发出的旧码里的旧入口仍须可服务，否则旧码等同作废——发码前先确认该入口的 Nginx 放行已就位。
- 落点页与 `/download/` 静态页一样在 80 明文 HTTP 上服务（沿 ADR 0004/0005/0012）：二维码链接与安装包 URL 同协议，避免「HTTPS 页面下载明文包」被 Chrome 判为不安全下载。IP 入口要在宿主 Nginx 上单独开一块 server 放行 `/download/`（域名块的放行不覆盖 IP），这块属于用户侧运维配置。
- 落点页是服务端按令牌渲染的单文件 HTML（不是静态文件，也不写进 `server/public`）：改它的样式/文案＝重发 backend-next 镜像；`/download/q/:token` 系路由先于 `/download/` 的静态通配匹配。
- 令牌格式有守卫（base64url 字符集 + 长度区间）：既是校验前提，也是落点页模板的注入防线；恒定时间比较仅作卫生，令牌本身不是密钥。
- 无扫码统计：扫了多少次、谁扫的都不记录（有意为之），需要时另立方案。
- 管理端新增 Settings 页「下载二维码」标签：日期时间选择器 + 1/7/30 天快捷预设，已有有效码时需二次确认才重掷；「保存二维码图片」由前端把渲染结果存为 PNG。
