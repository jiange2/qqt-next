# 媒体 Key 原名加密命名（文件名即密文）

为彻底隐藏 OSS 上的原始文件名，backend-next ADR 0008 决定：**原名加密后直接写入对象 key**，取代此前"rand 前缀 + 明文原名"的命名规范（ADR 0005 已于该规范回退时删除，本次再次推翻其中"保留原名"部分）。**否决了先前的"Object Metadata 存加密原名"方案**——那需要对每个对象额外发 HEAD 请求才能在列表中展示原名；key 即密文则让 `listV2` 列举一次拿全，零额外请求，解密是本地计算。

## 命名公式

| 类型 | key 形态 | 说明 |
|---|---|---|
| 音频 / 横幅图 / 歌单图（原"保留原名"类型） | `rand(0,999999)_<Base64url(AES-256-ECB(原名))>.<ext>` | 密文段带 `enc1:` 版本前缀 |
| 缩略图 / LRC / 专辑 / 歌手 / 分类图（固定标签类型） | `rand_<label>.<ext>` | 不变，原名本就丢弃 |

- **扩展名保持明文**：URL Content-Type 推断、前端预览依赖它，加密无收益。
- **密文用 Base64url**（`+/` → `-_`）：标准 Base64 的 `/` 会被 OSS 解析为目录分隔符。
- **rand 前缀保留**：ECB 是确定性加密，同名文件密文相同；无 rand 时第二次上传同名必然撞 key。撞 key 仍走既有 `objectExists` 查重 + 重摇（上限 10 次）。
- **原名截 128 字符**后再加密，防长名密文把 key 推近 OSS 1023 字节上限。
- 缩略图与原图仍同名异目录（`images/` 与 `images/thumbs/`），机制不变。

## 加密与密钥

- AES-256-ECB，密钥环境变量 `OSS_NAME_SECRET`（任意字符串，内部 sha256 派生 32 字节）。
- **未配置即启动失败（fail fast）**：杜绝"以为加密了其实明文"的静默降级。
- 密文带 `enc1:` 版本前缀：将来换算法/换密钥时可区分格式；密钥轮换后旧密文解密失败按回退策略处理。

## 解密展示与搜索

- `GET /admin/oss/objects` 全量列举某目录（防御上限 5000，超出标 `truncated`），服务端对每个 key 尾段解密，返回 `originalName?`；**keyword 过滤与分页均在前端本地做**（删除原服务端 keyword 跨页扫描与 token 游标）。
- `GET /admin/oss/decode?name=<文件名>`：单条解密，编辑表单（UploadField 绑定态）显示原名用。
- 前端不持有密钥；解密失败/非密文 key（存量）一律回退显示 key 尾段，绝不打断界面。
- keyword 同时匹配解密原名与 key 尾段。

## 外链转 OSS 命名来源修订

`transferExternalToOss` 原按 URL 末段文件名命名，但外链文件名可能是乱码长哈希。改为：**命名原文优先用歌曲 title**，为空回退 URL 末段；扩展名取 URL 末段（不像扩展名则回退 `.mp3`）。URL 解析不出文件名不再直接报错（title 通常恒存在）。

## Considered Options

- **Object Metadata 存加密原名**：随对象自包含，但列表需逐对象 `getObjectMeta`（HEAD），性能随对象数线性下降；Tagging 备选有 256 字符值上限硬伤；均被否。
- **MySQL 映射表**：列表零额外请求，但覆盖不了 OSS 管理页的孤儿文件，且不随对象走，被否。
- **CBC 随机 IV 替代 rand 前缀**：密文天然唯一可省 rand，但实现复杂度高于复用现有重摇机制，被否。

## Consequences

- 存量明文原名 key 不迁移、不重命名（沿用"存量不动"原则），隐藏对新上传渐进生效；需要时再单独做批量匿名化工具。
- OSS 上的对象名不再有语义，一切人读信息依赖管理面板的解密展示；直接看 bucket 无法得知文件内容对应的歌。
- `OSS_NAME_SECRET` 成为关键配置：丢失即永久无法解出存量密文 key 的原名（仍可回退显示 key，业务不受损）。
- 密文 key 使 URL 变长且不可读，但客户端只用完整 URL，不受影响。
