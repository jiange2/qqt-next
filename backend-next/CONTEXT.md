# Backend-Next（下一代后端）

用 Node.js + TypeScript 重写的音乐内容管理与分发上下文，最终替换 PHP 版 Backend。对 App 保持旧协议语义兼容（见根级 ADR 0003），对管理员提供全新的 Vue 管理面板。

## Language

### 架构

**遗留协议门面（Legacy Facade）**:
以旧 sign/salt 协议形态（`/legacy` 路由）对 App 暴露的兼容层，内部调用现代服务层。它复刻旧响应的字段名与类型形态，但不复刻旧实现。今后所有对 App 的协议变更必须经过门面策略评审（两端同步迁移）。
_Avoid_: 兼容层、旧接口（口语可用，正式场合用遗留协议门面）

**管理端 API**:
`/admin` 路由下的 REST/JSON 接口 + JWT 鉴权，仅供管理面板调用。与遗留协议门面共享服务层，但永不暴露给 App。
_Avoid_: 后台接口、内部接口

**热门榜**:
管理员在后台手工固定的歌曲集合（可排序），首页 `trending_songs` 的唯一数据来源。**语义变化**：旧 Backend 中「热门歌曲」按播放量自动排序，本上下文中由人工策展取代。
_Avoid_: 热门歌曲（旧语义）、趋势歌曲

**归属链**:
歌曲对 App 的从属路径：歌曲 → 专辑 → 分类（ADR 0009）。歌曲自身不再直接挂分类参与可见性；App 端内容接口经此链过滤（歌、专辑、分类三者 status 为真且专辑已归分类）。
_Avoid_: 二级结构、层级关系（口语）

**未分类**:
categoryId 为空的歌曲归属状态。**过渡期语义**（ADR 0009）：字段与后台 UI 暂留但已无行为语义，可见性与它无关；二期随字段一并拆除。
_Avoid_: 无分类、默认分类（不存在“默认”概念）

### 迁移与切换

**割接**:
一次性的新旧系统切换操作：冻结旧后台写入 → 运行迁移脚本 → 契约验证 → 切换流量 → PHP 下线。割接之后旧库即封存，不存在双写期。
_Avoid_: 切换、上线（太泛）

**黄金样本**:
在旧栈上预先录制的代表性 API 请求-响应对，作为割接前契约验证与回归测试的基准。
_Avoid_: 录制用例、快照测试

**继承 ID**:
迁移时保留旧库的实体主键值不重新编号，使媒体文件名、既有引用与管理员认知保持连续。
_Avoid_: 旧 ID、数据映射

### 运营与策展

**维度顺序**:
管理员手工固定的展示顺序，现为两个维度：**专辑在分类内**（`albums.category_sort`，App 分类专辑页顺序）与**歌曲在专辑内**（`songs.album_sort`，App 专辑歌曲页顺序），均为 sort ASC + id DESC 兜底、新加入插入最前（min-1）、移出归零。「按名称排序」/「按名称倒序」是建立维度顺序的快捷方式：以名称自然升序/降序一键重排，保存前仅为预览，保存后成为正式维度顺序。分类内歌曲排序已随 `cat_songs` 删除而消亡（ADR 0009）。
_Avoid_: 歌曲排序（太泛）、拖动顺序（仅描述交互）、文件名排序（实为按名称 title/name，非文件名）

**未分类专辑**:
categoryId 为空的专辑。仅存在于管理后台，App 分类下不可见，**其内歌曲级联不可见**。删除仍有专辑的分类被阻止（须先移走专辑）。存量专辑割接时全部置空，由管理员在后台逐个分配。
_Avoid_: 无分类专辑、孤儿专辑

**未归专辑**:
albumId 为空的歌曲归属状态。后台过滤、批量修改提供「未归专辑」作为出口选项；未归专辑歌曲对 App 完全不可见（与未分类专辑内歌曲同为不可见的两大来源，见 ADR 0009）。
_Avoid_: 无专辑、孤儿歌曲

### 数据边界

**内容资产**:
割接时迁移的对象全体：歌曲、分类、艺术家、专辑、播放列表、横幅、全局设置与媒体文件。
_Avoid_: 全量数据

**行为数据**:
挂在用户身上的数据（收藏、评论、举报、建议、活跃日志）及用户账户本身。**割接时全部放弃**，新系统从零积累。
_Avoid_: 用户数据（歧义：设置表中与用户相关的配置不算）

### 存储

**媒体 Key**:
数据库中存储的媒体对象标识（文件名），不含任何 endpoint 或域名。对外 URL 一律运行时按公网 Base 拼接（文件名部分编码），禁止把完整 URL 写入数据库。命名规则（ADR 0008）：随机前缀 + **加密原名**/固定标签——音频、横幅图、歌单图的原名经 AES-256-ECB 加密（Base64url，带 `enc1:` 前缀）后写入 key，扩展名保持明文；歌曲缩略图、LRC、专辑/歌手/分类图用固定标签。同名冲突重摇随机数；存量明文原名 key 不迁移。原名的解密展示仅存在于管理面板（OSS 管理/选择器/表单绑定值），前端不持有密钥。
_Avoid_: 文件路径、媒体地址（存库语义）、明文原名 key（新上传已不存在，仅存量）

**绑定**:
业务记录（歌曲/分类/艺术家/专辑/横幅/播放列表）通过存储的媒体 Key 与 OSS 对象建立的同名逻辑关联——无外键，可多记录共享同一对象，删除对象时按引用计数拦截。编辑表单回填绑定值供管理员确认；替换只靠重新上传或重新选择，不提供"解绑"操作。
_Avoid_: 解绑（不存在的操作）、外键关联（绑定是同名约定，非数据库约束）

**公网 Base**:
拼接对外媒体 URL 的基地址（OSS_PUBLIC_BASE）：当前指向 CDN 加速域名（明文 HTTP，长期不上 HTTPS）。只存在于配置中，永不出现在数据里。
_Avoid_: 媒体域名、下载地址

**防盗链 Referer**:
客户端访问 CDN 媒体时主动携带的约定身份标记：`http://com.qqt.music/`（包名作 host，并非真实来源页面）。CDN 白名单按域名 `com.qqt.music` 匹配；音频目录禁止空 Referer，图片/歌词目录允许空以保住管理面板的 IP Referer。换值 = App 发版（ADR 仓库级 0006）。
_Avoid_: 假 Referer（口语）、来源页面（不是真实来源）

**内网 Endpoint**:
上传专用 OSS 通道（OSS_INTERNAL=true，SDK internal 参数自动切 -internal 域名）：与 bucket 同 region 的服务器内网流量免费。仅用于服务端写对象，不参与对外 URL 拼接。
_Avoid_: 内部链接、内网地址（歧义）

**OSS 绑定**:
表单字段直接引用 OSS 已有对象的媒体 Key（不复制文件），与新上传二选一。绑定时只能从该字段的显示目录中选择（如封面只能从缩略图目录绑定），选择器中目录固定不可切换。
_Avoid_: 引用、关联（泛称，不体现目录约束）

**封面**:
歌曲缩略图（thumbnail）的口语同义词。批量绑定时多首歌指向同一个媒体 Key（共享引用），不复制文件；删除该对象时按引用计数提示。
_Avoid_: 海报、插图（其它实体图片用各自固定标签命名，不叫封面）
