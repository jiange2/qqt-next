# Backend-Next（下一代后端）

用 Node.js + TypeScript 重写的音乐内容管理与分发上下文，最终替换 PHP 版 Backend。对 App 保持旧协议语义兼容（见根级 ADR 0003），对管理员提供全新的 Vue 管理面板。

## Language

### 架构

**遗留协议门面（Legacy Facade）**:
以旧 sign/salt 协议形态（`/legacy` 路由）对 App 暴露的兼容层，内部调用现代服务层。它复刻旧响应的字段名与类型形态，但不复刻旧实现。今后所有对 App 的协议变更必须经过门面策略评审（两端同步迁移）。
_Avoid_: 兼容层、旧接口（口语可用，正式场合用遗留协议门面）

**管理端 API**:
`/admin` 路由下的 REST/JSON 接口 + JWT 鉴权，仅供管理面板调用。与遗留协议门面共享服务层，但永不暴露给 App。
_Avoid_: 后台接口、内部接口

**热门榜**:
管理员在后台手工固定的歌曲集合（可排序），首页 `trending_songs` 的唯一数据来源。**语义变化**：旧 Backend 中「热门歌曲」按播放量自动排序，本上下文中由人工策展取代。
_Avoid_: 热门歌曲（旧语义）、趋势歌曲

**归属链**:
歌曲对 App 的从属路径：歌曲 → 专辑 → 分类（ADR 0009）。歌曲自身不再直接挂分类参与可见性；App 端内容接口经此链过滤（歌、专辑、分类三者 status 为真且专辑已归分类）。隐私模式下可见性额外要求归属链全链非隐私（自身、专辑、分类的隐私标记均为假，见「隐私内容」）。
_Avoid_: 二级结构、层级关系（口语）

**未分类**:
categoryId 为空的歌曲归属状态。**过渡期语义**（ADR 0009）：字段与后台 UI 暂留但已无行为语义，可见性与它无关；二期随字段一并拆除。
_Avoid_: 无分类、默认分类（不存在“默认”概念）

### 迁移与切换

**割接**:
一次性的新旧系统切换操作：冻结旧后台写入 → 运行迁移脚本 → 契约验证 → 切换流量 → PHP 下线。割接之后旧库即封存，不存在双写期。
_Avoid_: 切换、上线（太泛）

**黄金样本**:
在旧栈上预先录制的代表性 API 请求-响应对，作为割接前契约验证与回归测试的基准。
_Avoid_: 录制用例、快照测试

**继承 ID**:
迁移时保留旧库的实体主键值不重新编号，使媒体文件名、既有引用与管理员认知保持连续。
_Avoid_: 旧 ID、数据映射

### 运营与策展

**维度顺序**:
管理员手工固定的展示顺序，现为三个维度：**专辑在分类内**（`albums.category_sort`，App 分类专辑页顺序）、**歌曲在专辑内**（`songs.album_sort`，App 专辑歌曲页顺序）与**书籍在分类内**（`books.category_sort`，App 书籍列表页顺序），均为 sort ASC + id DESC 兜底、新加入插入最前（min-1）、移出归零。「按名称排序」/「按名称倒序」是建立维度顺序的快捷方式：以名称自然升序/降序一键重排，保存前仅为预览，保存后成为正式维度顺序。分类内歌曲排序已随 `cat_songs` 删除而消亡（ADR 0009）。
_Avoid_: 歌曲排序（太泛）、拖动顺序（仅描述交互）、文件名排序（实为按名称 title/name，非文件名）

**未分类专辑**:
categoryId 为空的专辑。仅存在于管理后台，App 分类下不可见，**其内歌曲级联不可见**。删除仍有专辑的分类被阻止（须先移走专辑）。存量专辑割接时全部置空，由管理员在后台逐个分配。
_Avoid_: 无分类专辑、孤儿专辑

**未归专辑**:
albumId 为空的歌曲归属状态。后台过滤、批量修改提供「未归专辑」作为出口选项；未归专辑歌曲对 App 完全不可见（与未分类专辑内歌曲同为不可见的两大来源，见 ADR 0009）。
_Avoid_: 无专辑、孤儿歌曲

**隐私模式**:
settings 单行上的全局开关（`privacyMode`，存 `"true"/"false"`）。打开时 App 侧遗留协议门面只返回非隐私内容，关闭时全量返回。管理面板不受开关影响，始终全量可见。
_Avoid_: 隐私政策（`appPrivacyPolicy` ——应用合规文本，与隐私模式无关）、私密模式

**隐私内容**:
被标记 `is_private = true` 的歌曲/专辑/分类的合称。可见性按归属链级联计算（与 status 同构）：歌曲可见要求自身、所属专辑、所属分类均非隐私；专辑可见要求自身、所属分类均非隐私。新上传内容默认隐私（`is_private = true`），存量迁移置 false（非隐私）。
_Avoid_: 私密内容（用户口语可用，域内统一用隐私内容）

**隐私标记**:
内容条目上的 `is_private` 布尔字段。与 status（下架）正交：下架为恒定不可见，隐私为条件不可见——仅在隐私模式打开时生效。
_Avoid_: 隐藏（与下架语义混淆）、可见性标签（太泛）

### 数据边界

**内容资产**:
割接时迁移的对象全体：歌曲、分类、艺术家、专辑、播放列表、横幅、全局设置与媒体文件。
_Avoid_: 全量数据

**行为数据**:
挂在用户身上的数据（收藏、评论、举报、建议、活跃日志）及用户账户本身。**割接时全部放弃**，新系统从零积累。
_Avoid_: 用户数据（歧义：设置表中与用户相关的配置不算）

### 存储

**媒体 Key**:
数据库中存储的媒体对象标识（文件名），不含任何 endpoint 或域名。对外 URL 一律运行时按公网 Base 拼接（文件名部分编码），禁止把完整 URL 写入数据库。命名规则（ADR 0008）：随机前缀 + **加密原名**/固定标签——音频、横幅图、歌单图的原名经 AES-256-ECB 加密（Base64url，带 `enc1:` 前缀）后写入 key，扩展名保持明文；歌曲缩略图、LRC、专辑/歌手/分类图用固定标签。同名冲突重摇随机数；存量明文原名 key 不迁移。原名的解密展示仅存在于管理面板（OSS 管理/选择器/表单绑定值），前端不持有密钥。
_Avoid_: 文件路径、媒体地址（存库语义）、明文原名 key（新上传已不存在，仅存量）

**歌词密文**:
LRC 文件经上传侧加密后写入 OSS 的内容形态（`elrc1:` 前缀文本，口令双端共享、App 端内置）。仅覆盖新上传的 lrc 文件；内容无前缀即明文（存量文件、内嵌歌词文本、旧后台上传一律维持明文），下载方按前缀判定是否解密。
_Avoid_: 加密歌词（易误读为功能名）、歌词加密（指行为，形态名是密文）

**媒体混淆**:
音频与图片对象在 OSS 上的存储内容形态：逐字节 +31（模 256）的确定性变换，无密钥，取用方（App 播放与图片加载）自行 -31 还原（仓库级 ADR 0011）。已混淆对象以自定义元数据 `encrypted=1` 标记，批量补混淆据此跳过；歌词不参与（另有真加密，见「歌词密文」）。管理界面按钮文案可用「加密」，域内一律称混淆。
_Avoid_: 媒体加密（真加密是歌词密文的事）、解密（还原，无密钥）

**绑定**:
业务记录（歌曲/分类/艺术家/专辑/横幅/播放列表）通过存储的媒体 Key 与 OSS 对象建立的同名逻辑关联——无外键，可多记录共享同一对象，删除对象时按引用计数拦截。编辑表单回填绑定值供管理员确认；替换只靠重新上传或重新选择，不提供"解绑"操作。
_Avoid_: 解绑（不存在的操作）、外键关联（绑定是同名约定，非数据库约束）

**公网 Base**:
拼接对外媒体 URL 的基地址（OSS_PUBLIC_BASE）：当前指向 CDN 加速域名（明文 HTTP，长期不上 HTTPS）。只存在于配置中，永不出现在数据里。
_Avoid_: 媒体域名、下载地址

**防盗链 Referer**:
客户端访问 CDN 媒体时主动携带的约定身份标记：`http://com.qqt.music/`（包名作 host，并非真实来源页面）。CDN 白名单按域名 `com.qqt.music` 匹配；音频目录禁止空 Referer，图片/歌词目录允许空以保住管理面板的 IP Referer。换值 = App 发版（ADR 仓库级 0006）。
_Avoid_: 假 Referer（口语）、来源页面（不是真实来源）

**内网 Endpoint**:
上传专用 OSS 通道（OSS_INTERNAL=true，SDK internal 参数自动切 -internal 域名）：与 bucket 同 region 的服务器内网流量免费。仅用于服务端写对象，不参与对外 URL 拼接。
_Avoid_: 内部链接、内网地址（歧义）

**缓存头**:
媒体对象上的 HTTP 缓存指令（Cache-Control），仅 `max-age=<秒>` 单一形态——媒体 Key 内容不可变（替换即新 Key 改绑），长效缓存无过期风险，故否定性指令无场景。以 OSS 对象元数据为唯一事实、不落库，管理面板按需查看与批量设置；新上传默认按目录区分：图片 365 天、歌词 30 天、音频不设。与统计域「缓存命中」（App 本地缓存）无关，本词条指 CDN/HTTP 层缓存。
_Avoid_: 缓存策略（泛称）、no-cache（无场景）、缓存命中（混用统计域概念）

**OSS 绑定**:
表单字段直接引用 OSS 已有对象的媒体 Key（不复制文件），与新上传二选一。绑定时只能从该字段的显示目录中选择（如书籍封面从 images/ 绑定、分类图从缩略图目录绑定），选择器中目录固定不可切换。
_Avoid_: 引用、关联（泛称，不体现目录约束）

**封面**:
书籍的展示图（Book.cover）；歌曲等其它业务图不叫封面，叫缩略图。上传与其它业务图同库 images/，缩略图同名派生 720px（书单大卡可辨性，ADR 0011 修订）；App 书单页消费缩略图。批量绑定时多本书指向同一个媒体 Key（共享引用），删除对象时按引用计数提示。
_Avoid_: 海报、插图、歌曲封面（歌曲图片叫缩略图）

### 统计

**访问事实**:
一次装载播放的不可变流水记录，append-only，同一曲目的重复访问产生多条，不去重、不聚合。以 song_id 为权威身份（播放 URL 会随公网 Base 与重传漂移，不落库），命中与否由客户端在装载时刻判定（口径见 Android 上下文「整曲命中」），IP、User-Agent 与时间由服务端补齐。事实携带上报时刻的应用版本（客户端 versionName，老事实与未上报客户端为 NULL，管理端显示未知）。已下载歌曲的本地播放同样上报并计为命中（未产生媒体网络流量的装载均入命中侧）；离线播放因无网不可上报，缺失属口径内。事实无字节维度——访问明细、当日访问分解等展示均为次数口径，真实流量以 CDN 日志为准。指向的歌曲被删除后事实保留，展示为已删除歌曲。
_Avoid_: mp3_path 身份（demo 遗产，靠清洗文件名反查歌曲）, 字节口径（本上下文无 fileSize/data_size）, 去重（口径上永不）, 离线补报（无网即丢，不缓存重试）, 设备版本表（版本随事实上报，设备快照取最新事实）

**最近上报 IP**:
设备最新一条访问事实所带的 IP——IP 是访问事实的属性，随设备网络环境漂移，设备快照即以它代表「设备的 IP」；只认最新，历史 IP 不去重不展示，管理端完整明文显示。
_Avoid_: 设备 IP（IP 属事实非设备，设备无固有 IP）、历史 IP 集合（不采集不展示）、打码 IP（管理端完整显示）

**命中率**:
缓存命中情况的度量，**条数口径**：命中事实条数 ÷ 全部事实条数，每条事实一票（歌曲为单位）。命中 = 该次装载未产生媒体网络流量（整曲命中被动缓存，或本地播放）。
_Avoid_: 字节口径（demo 口径，本上下文明确不采用——装载即计整曲字节、不反映真实听播）, 条数命中率（本上下文唯一口径，无需限定词）

**在线状态**:
设备是否正在听歌的推导态，无独立标记字段、无下线信号：在线 ≡ 预期下线时间晚于当前时刻。预期下线时间在事实到达时按该设备（设备 ID，见 Android 上下文）覆写为「上报时刻 + 曲时长 + 1 分钟冗余」，时长取 songs.duration（由 App 端写回，见 Android 上下文「时长写回」），缺失/为 0 时仅加 1 分钟。已知误差：暂停或离开后无下线事件，继续显示在线至窗口过期（约一曲 + 1 分钟），接受此口径。
_Avoid_: online 字段（独立布尔 + 清扫任务已否决，渲染层实时推导）, 心跳, 下线事件, Agent（同一概念，Android 上下文的权威词是设备 ID）

### 阅读

**书籍**:
以章节组织的可阅读文本内容实体，归属书籍分类，正文经章节下发；与歌曲、专辑互不隶属。
_Avoid_: 小说、电子书

**书籍分类**:
分类的类型之一（另一类型为音乐分类，下挂专辑），下挂书籍而非专辑。
_Avoid_: 书分类、书城

**章节**:
书籍按序划分的内容单元，正文以章节为最小单位存储与下发。
_Avoid_: 回目、篇

**章节顺序**:
书内章节的展示序，与「维度顺序」（分类内归属序）并列互不隶属：逐章录入与 TXT 导入的先后即初值（新增章节追加书末），管理员在章节管理抽屉拖拽或按名称排序调整，保存后全量归位；未手动排序的存量按录入先后兜底。
_Avoid_: 维度顺序（章节顺序不是分类内维度）、拖动顺序（仅描述交互）

**智能分章节**:
后台上传整本 TXT、按章节标记族自动切分的录入方式：先展示切分出的章标题清单（可改标题、并章），确认后才入库；目录连排、识别不出的行与超短章并入上一章，整本无标记收作单章「正文」。
_Avoid_: 自动拆分、AI 分章

**逐章录入**:
管理面板中手动创建章节、逐章录入正文的录入方式。
_Avoid_: 手动分章
